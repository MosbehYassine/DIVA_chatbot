Barèmes de calcul des efforts

 

Le programme d'estimation de l'effort à produire pour une migration base ses calculs sur une série de barèmes.
 

Des barèmes par défaut sont proposés : vous les trouverez dans le fichier paramètres MigrationEffortSample.txt, livré en exemple.

Vous pouvez personnaliser les barèmes à votre convenance. Pour cela :

  • Créez une copie du fichier d'exemple en la nommant MigrationEffort.txt.

  • Personnalisez les valeurs d'effort spécifiées dans ce fichier.

  • Les lignes de commentaires sont autorisées. Elles doivent débuter par un ";" (1er caractère effectif de la ligne).

  • Mettez cette copie en ligne avant de lancer le calcul d'estimation de l'effort.

 

On distingue deux grandes familles de barèmes :

  1. Barèmes d'estimation de l'ampleur d'une surcharge.

    • L'ampleur d'un objet est déterminée selon l'estimation de son volume : volume de la surcharge pour un objet personnalisé en surcharge ou volume global de l'objet pour un objet développé en spécifique.
      Elle est ensuite utilisée par les barèmes de calcul d'effort.
      Une ampleur peut prendre les valeurs suivantes : Faible, Moyenne et Importante.
      Elle est affichée dans la colonne "Ampleur surcharge" du tableau des efforts.
       

    • Les identifiants des barèmes de cette famille ont tous "Volume" pour suffixe et leurs formats sont tous identiques :
      <NomVolume> <L,M>n1,n2

      • <NomVolume> est l'identifiant du barème.

      • n1 et n2 sont deux nombres qui déterminent l'ampleur selon la règle suivante :
        Ampleur faible si le volume de (la surcharge de) l'objet <= n1.
        Ampleur moyenne si le volume de (la surcharge de) l'objet > n1 et <= n2.
        Ampleur importante si le volume de (la surcharge de) l'objet > n2.
         

    • Chaque type d'objets dispose de son propre barème. Les barèmes suivants sont utilisés :

      • FormVolume : volume d'un masque spécifique.
        Ce volume est représenté par le nombre d'objets du masque.

      • FormTreatmentVolume : volume des traitements d'un masque spécifique.
        Ce volume est représenté par le nombre de lignes de code des traitements du masque.

      • OverwriteFormVolume : volume de la surcharge d'un masque.
        Ce volume est représenté par le nombre de différences avec le masque de base.

      • OverwriteFormTreatmentVolume : volume des traitements de surcharge d'un masque.
        Ce volume est représenté par le nombre de lignes de code des traitements de surcharge du masque.

      • OverwriteDictionnaryVolume : volume de la surcharge d'un dictionnaire de données.
        Ce volume est représenté par le nombre de différences avec le dictionnaire de base.

      • OverwriteDictionnaryTreatmentVolume : volume des traitements de surcharge d'un dictionnaire de données.
        Ce volume est représenté par le nombre de lignes de code des traitements de surcharge du dictionnaire.

      • ModuleVolume : volume d'un module Diva spécifique.
        Ce volume est représenté par le nombre de lignes de code du module.

      • OverwriteModuleVolume : volume de la surcharge d'un module Diva.
        Ce volume est représenté par le nombre de lignes de code du module de surcharge.

    • Cas des masques (surchargés ou spécifiques) et des dictionnaires de données surchargés.
      Pour ces objets, deux volumes sont estimés (selon le nombre d’objets et le nombre de lignes de code des traitements).
      L'ampleur retenue sera ici le maximum des deux valeurs d'ampleur calculées.
       

    • Cas de tous les sources Diva.
      Aucune ampleur n'est affectée à un source Diva dont le nombre de fonctions / procédures (Main inclus) est nul.
       

    • Exemple.
      <OverwriteFormVolume> <L,M>30,100 signifie que l'ampleur estimée de la surcharge des masques sera :

      • Faible si le nombre de différences entre le masque surchargé et sa base ne dépasse pas 30.

      • Moyenne si le nombre de différences entre le masque surchargé et sa base est supérieur à 30 mais ne dépasse pas 100.

      • Importante si le nombre de différences entre le masque surchargé et sa base est supérieur à 100.
         

  1. Barèmes d'estimation d'un effort.

    • Ces barèmes fournissent les valeurs des estimations d'effort.
      Reportez-vous à la fin de cette rubrique pour prendre connaissance des différentes opérations prises en compte par le calcul d'effort.
       

    • Selon le type d'objet et l'opération, un ou plusieurs facteurs sont pris en considération pour une estimation :

      • Difficulty : niveau de difficulté estimé dans la base de données Migration de Divalto.
        Remarque : Ce facteur n'est valable que pour les objets personnalisés en surcharge (les objets spécifiques ne sont évidemment pas enregistrés dans la base).

      • Volume : volume estimé (de la surcharge) d'un objet.

      • Volume_V6_V7 : idem en cas de passage de la version 6 à la version 7
        (pour les masques et sans utilisation de la moulinette de conversion V6 => V7).

Si aucun des facteurs précédents ne convient, le facteur Default est pris par défaut.

Remarque importante :

Lorsque plusieurs facteurs s'appliquent à un même objet, la valeur estimée de l'effort est le maximum des valeurs calculées pour chacun des facteurs. D'autre part, aucune valeur n'est estimée si la difficulté spécifiée dans la base de donnée Migration vaut A réécrire ou Inconnue (un ? est affiché dans la colonne Effort estimé du tableau des efforts).
 

Cas particulier des masques :

Les barèmes par défaut considèrent que le passage d'un masque spécifique de la version 6 à la version 7 utilise la moulinette de conversion V6 => V7 et que la migration d'un masque surchargé utilise la fonction de mise à niveau des masques de Xwin.

    • Les valeurs d'effort estimées sont spécifiées comme suit.
      Format : <facteur-A,L,M,B>n1,n2,n3,n4  ou  <facteur-L,M,B>n1,n2,n3  ou  <facteur>n1

      • facteur : nom du facteur.

      • A : Difficulté Automatique.

      • L,M,B : Difficulté Simple,Moyenne,Complexe  ou  ampleur Faible,Moyenne,Importante.

      • n1,n2,n3,n4 : valeurs d'effort respectives.

Exemples :

<Difficulty-A,L,M,B>0,30,50,100 ==> effort lié au facteur "Difficulté" :
0    si la difficulté est Automatique
30  si la difficulté est Simple
50  si la difficulté est Moyenne
100 si la difficulté est Complexe.

<Volume-L,M,B>10,20,40 ==> effort lié au facteur "Volume" :
10 si l'ampleur est Faible
20 si l'ampleur est Moyenne
40 si l'ampleur est Importante.

 

Rappels :

  • La valeur estimée d'un effort est exprimée en "points d'effort".
    Il ne s'agit pas directement d'une estimation du temps de développement nécessaire à la migration. En effet, la notion de temps est très relative et dépend de divers facteurs. Par exemple, le développeur d'une surcharge aura sans doute plus de facilités à effectuer la migration qu'une personne n'y ayant pas directement participé.
     

  • La valorisation effective de l'effort de migration d'un objet est une opération manuelle.
    Au départ, chaque effort est initialisé à zéro. L'effort estimé par le programme est fourni à titre purement indicatif et affiché dans la colonne qui précède la valeur à saisir. L'effort doit être obligatoirement renseigné pour que l’objet concerné soit comptabilisé dans la totalisation de l’effort estimé. Une touche de fonction permet de transférer l'effort estimé dans la zone saisie.

 

Exemple d'estimations de l’effort - cas de la migration d’un masque surchargé et modifié par Divalto :

  • Le barème FormModif est utilisé.

  • Migration d'un masque d'une version 7.x à une version ultérieure.

    • Facteur Difficulty.
      Par défaut, la difficulté est positionnée à "Automatique" dans la base de données Migration. En effet, la migration se fera en principe en utilisant la fonction de mise à niveau des masques de surcharge de Xwin. La difficulté peut toutefois être réévaluée par Divalto, par exemple lorsque le masque a subi des modifications structurelles importantes.

      Le facteur <Difficulty-A,L,M,B>ed1,ed2,ed3,ed4 du barème FormModif est ici utilisé. Si la difficulté vaut Automatique, la valeur d'effort ed1 est retenue. Si la difficulté a par exemple été réévaluée à Moyenne, c'est la valeur d'effort ed3 qui sera retenue.
       

    • Facteur Volume.
      Deux valeurs d'ampleur de la surcharge sont d'abord évaluées, en utilisant les barèmes :

      • <OverwriteFormVolume> <L,M>n1,n2
        (volume basé sur le nombre de différences du masque de surcharge par rapport au masque de base).
        Exemple : si le nombre de différences est compris entre n1 et n2, cette première ampleur sera estimée à Moyenne.

      • <OverwriteFormTreatmentVolume> <L,M>l1,l2
        (volume basé sur le nombre de lignes de code des traitements de surcharge du masque).
        Exemple : si le nombre de lignes est supérieur à l2, cette deuxième ampleur sera estimée à Importante.

L'ampleur finalement retenue est la valeur maximale des deux valeurs d''ampleur précédentes (Importante dans notre exemple).

Ensuite, cette ampleur est utilisée pour déterminer le facteur <Volume-L,M,B>ev1,ev2,ev3.
Dans notre exemple (ampleur Importante), la valeur d'effort ev3 sera retenue.

    • Effort estimé.
      En final, l'effort estimé sera la valeur maximale des deux efforts calculés pour les facteurs Difficulty et Volume.
      Dans notre exemple : max (ed1,ev3) ou max (ed3,ev3) selon la difficulté (Automatique ou Moyenne).
       

  • Migration d'un masque d'une version 6.x à une version 7 ou ultérieure.
    On suppose ici que la moulinette de conversion en version 7 n'est pas utilisée puisqu'il s'agit de reporter les modifications du masque de surcharge V6 dans le masque de base V7 (déjà converti).
    Un autre facteur entre ici en ligne de compte, le facteur <Volume_V6_V7-L,M,B>ew1,ew2,ew3.
    Ce facteur fonctionne exactement sur le même principe que le facteur Volume précédemment décrit.
    L'effort estimé en final sera la valeur maximale des trois efforts calculés pour les facteurs Difficulty, Volume et Volume_V6_V7.

 

Opérations prises en compte par le calcul d'effort

  • SubProjectDel : sous-projet annulé par l'éditeur.

  • FormDel : masque annulé par l'éditeur.

  • FormModif : masque modifié par l'éditeur (aussi utilisé pour un masque non modifié par l'éditeur -difficulté Automatique-).

  • FormSpecif : masque spécifique.

  • ZoomModif : zoom, nom du masque modifié par l'éditeur (SQLisation).

  • ZoomSpecif : zoom spécifique (si SQLisation demandée).

  • ModuleDel : module annulé par l'éditeur.

  • ModuleSpecif : module spécifique.

  • DictionnaryDel : dictionnaire annulé par l'éditeur.

  • DictionnarySpecif : dictionnaire spécifique.

  • SqlDictionnaryDel : dictionnaire de recordSQL annulé par l'éditeur.

  • SqlDictionnarySpecif : dictionnaire de recordSQL spécifique.

  • DictionnaryColDelForm : champ annulé par l'éditeur (utilisation dans le dessin d'un masque).

  • DictionnaryColModifForm : champ modifié par l'éditeur (utilisation dans le dessin d'un masque).

  • DictionnaryColDelDiva : champ annulé par l'éditeur (utilisation en diva).

  • DictionnaryColModifDiva : champ modifié par l'éditeur (utilisation en diva).

  • DictionnaryTableDel : table annulée par l'éditeur.

  • DictionnaryTableMove : table déplacée par l'éditeur dans un autre fichier.

  • DictionnaryFileDel : fichier annulé par l'éditeur.

  • DictionnaryIndexDel : index annulé par l'éditeur dans le fichier.

  • DictionnaryIndexModif : index modifié par l'éditeur dans le fichier.

  • FunctionDel : fonction annulée par l'éditeur.

  • FunctionProtoModif : prototype de fonction modifié par l'éditeur.

  • MigrationPackage : forfait migration.

  • FormsConversionV6_V7 : forfait conversion des masques spécifiques de version 6 à 7.
