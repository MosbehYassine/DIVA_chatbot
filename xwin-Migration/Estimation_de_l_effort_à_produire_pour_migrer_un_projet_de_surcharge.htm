Estimation de l'effort à produire pour migrer un projet de surcharge

 

Cette fonction valorise (en points d’effort) l’inventaire des personnalisations, de manière à chiffrer le travail qui sera nécessaire pour réaliser la migration d'un projet de surcharge d'une version initiale vers une version cible de l'ERP Divalto. Elle interroge la base de données "Migration" de Divalto pour évaluer l’impact des évolutions apportées à l’ERP sur les personnalisations effectuées précédemment en surcharge.

 

La méthode pour estimer l'effort est basée sur les principes suivants :

  1. Le programme analyse les objets trouvés dans l'Inventaire des modifications apportées au projet de surcharge.
    Il se base donc sur la liste des personnalisations opérées sur les objets du projet de base et sur la liste des objets spécifiques développés.
     

  2. Pour un objet personnalisé en surcharge, la base de données "Migration" de Divalto est interrogée afin de savoir si cet objet existe toujours, s'il a été modifié en profondeur, etc. La base de données fournit également un "niveau de difficulté" estimé par Divalto pour la migration de l'objet.
     

  3. Selon son type, l'estimation de l'effort de migration d'un objet dépend d'un ou plusieurs facteurs : le niveau de difficulté trouvé dans la base Migration, le volume estimé de la surcharge pour un objet de base surchargé, le volume de développement estimé pour un objet spécifique, la nécessité de convertir les masques d'écran spécifiques de version 6 en version 7, la nécessité de "SQLiser" les masques des zooms, etc.
     

  4. Un barème est appliqué pour chaque facteur retenu.
    Lorsque plusieurs facteurs s'appliquent à un même objet, la valeur estimée de l'effort est le maximum des valeurs calculées pour chacun des facteurs.
    Des barèmes par défaut sont proposés mais vous avez la possibilité de les personnaliser.
     

  5. La valeur estimée d'un effort est exprimée en "points d'effort".
    Il ne s'agit pas directement d'une estimation du temps de développement nécessaire à la migration. En effet, la notion de temps est très relative et dépend de divers facteurs. Par exemple, le développeur d'une surcharge aura sans doute plus de facilités à effectuer la migration qu'une personne n'y ayant pas directement participé.
     

  6. Enfin, la valorisation effective de l'effort de migration d'un objet est une opération manuelle.
    Au départ, chaque effort est initialisé à zéro. L'effort estimé par le programme est fourni à titre purement indicatif et affiché dans la colonne qui précède la valeur à saisir. L'effort doit être obligatoirement renseigné pour que l’objet concerné soit comptabilisé dans la totalisation de l’effort estimé. Une touche de fonction permet de transférer l'effort estimé dans la zone saisie.
