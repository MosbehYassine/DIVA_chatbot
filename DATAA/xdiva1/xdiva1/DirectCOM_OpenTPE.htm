DirectCOM_OpenTPE Famille Thème

 

La fonction DirectCOM_OpenTPE permet d'ouvrir un port COM, dont elle cherche les paramètres dans le fichier fconfig.dhfi à destination d'un terminal de payement.

En particulier, cette fonction permet d'initialiser les éléments de protocole de communication nécessaires pour le dialogue avec un TPE, dont les particularités rendent impossible l'utilisation des fonctions standard de communication avec les voies séries.

 

int DirectCOM_OpenTPE (voie, TypeDeProtocolTPE, debug, TimeoutEnModeAttendre, LireReponseAussiEnModeAttendreDansLeWriteTPE )

 

Paramètres

 

voie

Numérique

numéro de la voie dans la tables des Devices de Harmony (voir Fonctions DirectCOM).

TypeDeProtocolTPE

Numérique (2,0)

facultatif. Seul le protocole CONCERT (identifié par la valeur par défaut, 0) est supporté à ce jour.

debug

Numérique (2,0)

Par défaut, ce paramètre vaut 0 et le mode debug n'est pas actif.

1 = passage en mode debug , dans ce mode la dll écrit des informations de debug dans le fichier DhDivaltoDirectPrinter.log qui se trouve dans DivaltoLog.

TimeoutEnModeAttendre

Numérique (5,0)

Timeout d'attente entendu pour le TPE, en secondes. Il est conseillé de mettre un temps d'attente relativement long (pour la saisie des codes de CB). L'ERP utilise 60 secondes comme valeur standard.

LireReponseAussiEnModeAttendreDansLeWriteTPE

Numérique (1,0)

Ce flag permet de lire les réponses du TPE même pendant l'exécution des fonctions write. Ce flag doit être positionné à 1, sinon les échanges de protocole qui ont lieu pendant l'écriture ne seront pas traités et le terminal sera en erreur.

 

 

Retour

 

0

Erreur

numéro de canal

Le numéro de canal qui doit être transmis aux fonctions de lecture et écriture sur ce canal par la suite.
