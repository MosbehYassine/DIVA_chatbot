Options du compilateur

Le compilateur est appelé depuis l'éditeur Xwin lors de la compilation d'un source,

 

Les options reconnues par le compilateur sont :

N

Cette option indique que le fichier objet doit être automatiquement créé s'il n'existe pas. Cette option est également valable pour les fichiers Listing et Journal.

D

Cette option indique que le fichier doit être compilé en mode Debug. Si cette option est absente, il ne sera pas possible de placer des points d'arrêts dans le module.

L+fichier

Cette option permet d'avoir un listing de compilation dans un fichier. L'option L doit être suivie du nom du fichier ; si ce nom contient des espaces, il doit être encadré par des quotes. Ex : L"fichier listing".

Z+fichier

Cette option permet d'avoir un listing de compilation contenant le source et le code généré dans un fichier. L'option Z doit être suivie du nom du fichier ; si ce nom contient des espaces, il doit être encadré par des quotes. Ex : Z"fichier listing".

C+fichier

Cette option permet d'avoir un compte-rendu de la compilation dans un fichier. Le compilateur génère une ligne de compte-rendu dans le cas où il y a eu des erreurs. L'option C doit être suivie du nom du fichier ; si ce nom contient des espaces, il doit être encadré par des quotes. Ex : C"compte rendu".

O+fichier

Cette option permet de préciser le nom du fichier objet. L'option O doit être suivie du nom du fichier ; si ce nom contient des espaces, il doit être encadré par des quotes. Ex : O"fichier objet".

T+fichier

Cette option est expliquée ci-dessous (paragraphe "Aide à la migration des applications").

K

Genère les informations de tous les enregistrements pour les instructions DataCompute, DataValue et DataDescriptor.

 

QA

Désactive toutes les optimisations de vitesse du compilateur.

 

QM

Le compilateur ne garde plus les prototypes des modules entre deux compilations.

 

QS

Le compilateur ne garde plus les sources des includes entre deux compilations.

 

QD

Le compilateur ne garde plus les structures chargées depuis le dictionnaire entre deux compilations.

 

Ces options peuvent être positionnées dans la gestion des projets au niveau du profil.

 

 

Aide à la migration des applications

Lors d'un changement de version, il est possible que des champs soient agrandis. Par exemple, le champ Dossier est passé de 3 positions numériques à 20 positions alphanumériques au passage à la version 10 de l'ERP Divalto.

De telles modifications peuvent entraîner des problèmes à l’exécution, si le développement des surcharges n’a pas été effectué selon les règles de l’art. Dans notre exemple, lorsqu’une donnée interne décrivant un dossier a été réservée par :

1 dossier 3,0

au lieu de :

1 dossier  >GTFDD.dhsd DOS


L’affectation du champ DOS d’une table dans le champ interne <dossier> ne génère pas d’erreur au moment de la compilation car cette écriture est admise par le langage Diva. Par contre, à l’exécution du programme, le champ DOS initial sera tronqué et converti en numérique dans la variable <dossier>.

Une option du compilateur Diva permet de détecter ce genre de problème dès la compilation en demandant un contrôle plus strict des affectations.


Le principe est le suivant :

  • Un fichier paramètre contient les noms des champs dont on veut surveiller l’affectation.

  • Si le compilateur détecte qu’on affecte dans un tel champ une donnée plus grande, le compilateur génère une erreur.

  • Si le compilateur a un doute (affectation d’un calcul ou d’une zone flottante), le compilateur génère un avertissement (warning).

Mise en œuvre

Ce contrôle est demandé par l'option Tfic (lettre T, suivie du nom du fichier paramètre).

 

Format du fichier paramètre

;Commentaire

<FIELD>dos

<FIELD>CoefPts

<FIELD>champ1

 

Détails

Le compilateur surveille :

  • Les champs de n’importe quel Record ou RecordSql.

  • Les données déclarées en  >dico champ
    Exemple :  1  MonDos >gtfdd.dhsd Dos

  • Les champs de Structures Diva déclarés en >dico champ

  • Ces champs dans des tableaux.

La surveillance s’exerce lors de l’affectation et lors du passage de paramètres avec un paramètre formel de taille fixe.

Le fichier FIELD_X2 livré sur le Master 212 de l’ERP contient la liste des champs concernés pour la version X.2.
