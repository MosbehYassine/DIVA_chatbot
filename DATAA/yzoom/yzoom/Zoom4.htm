ZoomSql

 

Un Zoom SQL peut être appelé depuis un programme Diva par la fonction ZoomSql.

 

Syntaxe :

ZoomSql  (&Zoom, RecordSql, MasqueEcran, ModuleTraitement, Privilege, Action, Recup, Mode)

 

 

Passage des paramètres :

Zoom est le nom d'une instance de l'enregistrement "Zoom" décrit dans le dictionnaire de données système ddsys.dhsd. C'est le seul paramètre obligatoire de la fonction Diva ZoomSql. Ensuite, deux méthodes (non exclusives) permettent de passer au programme xzoom7.dhop les autres paramètres nécessaires à la bonne exécution du zoom :

  • Les faire figurer directement dans l'instruction ZoomSql, à la suite du paramètre Zoom.
    Cette méthode permet, dans la plupart des cas, d'appeler un zoom en une seule instruction.
    Voir l'exemple 1.
     

  • Placer individuellement tout ou partie des paramètres dans l'enregistrement Zoom avant l'appel à la fonction ZoomSql.
    Bien entendu, les paramètres transmis dans l'enregistrement Zoom ne devront plus figurer en paramètres de la fonction ZoomSql.
    La fonction ne propose que les paramètres les plus courants : les paramètres d'entrée plus spécifiques doivent être chargés dans l'enregistrement Zoom.
    Voir l'exemple 2, qui mixte les deux méthodes de passage de paramètres.

 

Autres paramètres de la fonction ZoomSql :

  • RecordSql est le nom du RecordSql associé à la table traitée.

  • MasqueEcran est le nom de l'objet du masque d'écran du zoom.

  • ModuleTraitement le nom de l'objet du module de traitements du zoom.

  • Privilege est le niveau de privilège.

  • Action est le type d'action du scénario.

  • Recup est un booléen indiquant si l'on souhaite récupérer la valeur renvoyée par le zoom dans la donnée en cours de saisie. Ce paramètre n'est pas stocké dans l'enregistrement Zoom, il est traité par la fonction ZoomSql au retour du zoom. Si ce paramètre est positionné à TRUE et si Zoom.Status vaut E_ZOOM_OK, le champ Zoom.ValRetour est transféré dans la donnée en cours de saisie du masque courant.

  • Mode indique le mode d'appel du programme xzoom7.dhop :

    • CALL_WAIT (valeur par défaut) demande que le programme appelant attende la fin du zoom pour poursuivre son exécution.

    • CALL_NOWAIT demande que le programme appelant se poursuive immédiatement, sans attendre la fin du zoom. L'appelant et le zoom sont alors totalement autonomes.

    • La valeur 3 (à usage interne) permet d’appeler le zoom par ProgramGoto.

 

Retour du zoom :

Le zoom renvoie l'enregistrement Zoom dans le tunnel.

La fonction ZoomSql renvoie Zoom.Status.

 

 

Exemple 1 :

ZoomSql (Zoom, 'Article', 'me1.dhof', 'mod1.dhop', Action=ZOOM_STANDARD, Recup=TRUE)
 

Exemple 2 :

Zoom.SceAction = ZOOM_AFFICHAGE         ;paramètre de l'instruction ZoomSql
Zoom.Msqimp    = 'mi1.dhoi'             ;autre paramètre

ZoomSql (Zoom, 'Article', 'me1.dhof', 'mod1.dhop')

 

Remarque :

A l'instar de la fonction ProgramCall, la fonction ZoomSql provoque l'exécution du zoom dans un contexte distinct de celui du programme en cours d'exécution. S'il y a lieu de lui passer des paramètres complémentaires, il faut les envoyer dans le tunnel par l'instruction Ping et les récupérer dans la séquence ZoomDebut par la fonction PingReceive. De même, si le zoom doit renvoyer des informations au programme appelant (en dehors de Zoom.ValRetour), il faut les envoyer dans le tunnel par l'instruction Pong et les récupérer dans le programme appelant par la fonction PongReceive.

 

Attention :

Pour appeler un deuxième zoom depuis une procédure d'un premier zoom, il est impératif d'utiliser une autre instance de l'enregistrement Zoom. Pour cela, on déclarera l'enregistrement Zoom comme variable locale à la procédure en cours ou on déclarera une autre instance globale de l'enregistrement Zoom (avec un autre nom).

 

Exemple 3 :

Record ddsys.dhsd Zoom wZoom         ;ici une autre instance de zoom

Public Procedure ZoomConsult

Beginp

   If Harmony.Key = K_F8

      ZoomSql (wZoom, 'article', 'me1.dhof', 'mod1.dhop')

   Endif

Endp
