Objets pris en compte et objets ignorés dans le calcul des efforts

 

Cette rubrique dresse la liste des objets d'une surcharge, en précisant ceux qui sont ou non inventoriés et pris en compte dans le calcul de l'estimation de l'effort de migration (avec les barèmes associés). Elle explique aussi les restrictions et les conditions préalables à la bonne utilisation du programme d'estimation.

Remarque : Les calculs d'estimation utilisent la base de données Migration de Divalto. Le contenu de cette base est expliqué dans la rubrique Base de données Migration de Divalto.
 

  • Sources inventoriés.

    • Sous-projets surchargés.
      Un effort est estimé en cas de suppression du sous-projet de base par Divalto.
      Barème de référence : SubProjectDel.
      Facteur pris en compte : niveau de difficulté estimé dans la base Migration.
       

    • Dictionnaires de données (.dhsd) surchargés.
      L'inventaire répertorie l'ensemble des différences entre le dictionnaire de base et sa surcharge. A titre indicatif, sont affichés dans le tableau des efforts le nombre de différences par rapport à la base et le nombre de fonctions et de lignes de code des traitements de surcharge.
      Un effort est estimé en cas de suppression du dictionnaire de base par Divalto. L'estimation ne tient pas compte du détail des modifications apportées en surcharge (*).
      Barème de référence : DictionnaryDel.
      Facteurs pris en compte : Volume estimé de la surcharge (dictionnaire et traitements du dictionnaire), niveau de difficulté estimé dans la base Migration.

      (*) Il est possible que certaines anomalies produites par des modifications du dictionnaire de base ne soient pas détectées (par exemple, un champ de base supprimé et utilisé dans une table ou un index créé en surcharge). En revanche, d'autres anomalies produites par des modifications du dictionnaire de base seront détectées par ailleurs (voir "Autres objet inventoriés").
       

    • Dictionnaires de données (.dhsd) spécifiques.
      L'inventaire répertorie simplement le nom du dictionnaire. A titre indicatif, sont affichés dans le tableau des efforts le nombre de fonctions et de lignes de code de ses traitements.
      L'estimation de l'effort ne tient pas compte du volume du dictionnaire spécifique.
      Barème de référence : DictionnarySpecif.
      Facteur pris en compte : Aucun.
       

    • Masques d'écran et d'imprimante (.dhse, .dhsf et .dhsi) surchargés.
      L'inventaire répertorie l'ensemble des différences entre le masque de base et sa surcharge. A titre indicatif, sont affichés dans le tableau des efforts le nombre de différences par rapport à la base, le nombre de pages et d'objets du masque, ainsi que le nombre de fonctions et de lignes de code des traitements de surcharge.
      Un effort est estimé en cas de suppression ou de modification du masque de base par Divalto. L'estimation ne tient pas compte du détail des modifications apportées en surcharge.
      Barèmes de référence respectifs : FormDel ou FormModif.
      Facteurs pris en compte : Volume estimé de la surcharge (masque avec ou sans conversion en version 7 et traitements du masque), niveau de difficulté estimé dans la base Migration.
       

    • Masques d'écran et d'imprimante (.dhse, .dhsf et .dhsi) spécifiques.
      L'inventaire répertorie simplement le nom du masque. A titre indicatif, sont affichés dans le tableau des efforts le nombre de pages et d'objets du masque, ainsi que le nombre de fonctions et de lignes de code de ses traitements.
      Barème de référence : FormSpecif.
      Facteur pris en compte : Volume estimé (masque avec ou sans conversion en version 7 et traitements du masque).
       

    • Modules de programme Diva (.dhsp) surchargés.
      L'inventaire répertorie simplement le nom du module. A titre indicatif, sont affichés dans le tableau des efforts le nombre de fonctions et de lignes de code du module de surcharge.
      Un effort est estimé en cas de suppression du module de base par Divalto.
      Barème de référence : ModuleDel.
      Facteurs pris en compte : Volume estimé de la surcharge, niveau de difficulté estimé dans la base Migration.
       

    • Modules de programme Diva (.dhsp) spécifiques.
      L'inventaire répertorie simplement le nom du module. A titre indicatif, sont affichés dans le tableau des efforts son nombre de fonctions et de lignes de code.
      Barème de référence : ModuleSpecif.
      Facteur pris en compte : Volume estimé.
       

    • Dictionnaires de RecordSql (.dhsq) surchargés.
      L'inventaire répertorie simplement le nom du dictionnaire de RecordSql (sans aucun détails).
      Un effort est estimé en cas de suppression du dictionnaire de base par Divalto. L'estimation ne tient pas compte du volume estimé du dictionnaire.
      Barème de référence : SqlDictionnaryDel.
      Facteur pris en compte : niveau de difficulté estimé dans la base Migration.
       

    • Dictionnaires de RecordSql (.dhsq) spécifiques.
      L'inventaire répertorie simplement le nom du dictionnaire de RecordSql (sans aucun détails).
      L'estimation ne tient pas compte du volume estimé du dictionnaire.
      Barème de référence : SqlDictionnarySpecif.
      Facteur pris en compte : Aucun.
       

    • Dictionnaires de jointures (.dhsj).
      Les dictionnaires de jointures ne sont pas inventoriés et sont ignorés lors des estimations d'effort.

       

  • Autres objets inventoriés.

    • Zooms surchargés.

      Attention       :
      La famille Zooms de l'inventaire liste tous les masques des zooms surchargés.
      La famille Zooms du tableau des efforts liste uniquement les masques des zooms dont le nom du masque a été modifié par Divalto (ce qui généralement signifie que ce zoom a été "SQLisé" en standard).
      Les masques des autres zooms surchargés devront être valorisés en tant que masques "normaux".
      Rappel : Les modules de traitements des zooms sont toujours valorisés en tant que modules "normaux".

      L'estimation se base exactement sur les mêmes données qu'un masque surchargé "normal" mais avec un autre barème de référence. On considère en effet que le travail à effectuer n'est pas identique dans les deux cas, la fonction de mise à niveau des masques de Xwin ne s'appliquant pas aux masques SQLisés (qui ont changé de format).

      Barème de référence : ZoomModif.
      Facteurs pris en compte : Volume estimé du masque avec ou sans conversion en version 7, niveau de difficulté estimé dans la base Migration.
       

    • Zooms spécifiques.

      Attention       :
      La famille Zooms spécifiques de l'inventaire liste tous les masques des zooms spécifiques.
      La famille Zooms spécifiques du tableau des efforts contient la même liste, à condition que l'option "SQLisation des zooms" ait été activée au moment d'exécuter le calcul d'estimation des efforts.
      A défaut, cette liste reste vide et les masques des zooms spécifiques devront être valorisés en tant que masques "normaux".
      Rappel : Les modules de traitements des zooms sont toujours valorisés en tant que modules "normaux".

      L'estimation se base exactement sur les mêmes données qu'un masque spécifique "normal" mais avec un autre barème de référence. On considère en effet que le travail à effectuer n'est pas identique dans les deux cas, la SQLisation s'accompagnant d'un changement de format du masque.

      Barème de référence : ZoomSpecif.
      Facteur pris en compte : volume estimé du masque avec ou sans conversion en version 7.
       

    • Fonctions.
      L'inventaire répertorie les fonctions de base appelées en surcharge ou en spécifique. A titre indicatif, le nombre d'appels est affiché dans le tableau des efforts.
      Un effort est estimé en cas de suppression de la fonction de base (ou du module complet la définissant) par Divalto ou si le prototype de la fonction a été modifié significativement. L'estimation ne tient pas compte du nombre d'appels aux fonctions.
      Barèmes de référence respectifs : FunctionDel ou FunctionProtoModif.
      Facteur pris en compte : niveau de difficulté estimé dans la base Migration.
       

    • Hfiles.
      L'inventaire répertorie les instructions Diva "Hfile" référençant un fichier de base et utilisées en surcharge ou en spécifique. A titre indicatif, le nombre d'utilisations est affiché dans le tableau des efforts, ainsi qu'une sous-liste présentant l'ensemble des modifications faites par Divalto sur les index du fichier (le cas échéant).
      Un effort est estimé en cas de suppression du fichier par Divalto, si un index a été supprimé pour ce fichier ou si un index a été modifié. L'estimation ne tient pas compte du nombre d'utilisations du Hfile.
      Barèmes de référence respectifs : DictionnaryFileDel, DictionnaryIndexDel ou DictionnaryIndexModif.
      Facteur pris en compte : niveau de difficulté estimé dans la base Migration.

      Remarque importante       : Un poste de valorisation est créé pour tout fichier dont les index ont été modifiés ou supprimés par Divalto. Toutefois, cela ne signifie pas qu'un travail d'adaptation de la surcharge est toujours nécessaire. En effet, il est possible que les index concernés NE soient PAS utilisés par la surcharge.
       

    • Records.
      L'inventaire répertorie les tables de base utilisées en surcharge ou en spécifique. A titre indicatif, le nombre d'utilisations est affiché dans le tableau des efforts.
      Un effort est estimé en cas de suppression de la table par Divalto ou si la table a été déplacée dans un autre fichier. L'estimation ne tient pas compte du nombre d'utilisations du Record.
      Barèmes de référence respectifs : DictionnaryTableDel ou DictionnaryTableMove.
      Facteur pris en compte : niveau de difficulté estimé dans la base Migration.
       

    • Records SQL.
      Les tables SQL de base utilisées en surcharge ou en spécifique sont inventoriées mais sont ignorés lors des estimations.
       

    • Champs diva.
      L'inventaire répertorie les champs de base utilisés dans un source Diva (y compris les traitements de masques ou de dictionnaires) en surcharge ou en spécifique. A titre indicatif, le nombre d'utilisations est affiché dans le tableau des efforts.
      Un effort est estimé en cas de suppression ou de modification du champ par Divalto. L'estimation ne tient pas compte du nombre d'utilisations du champ.
      La présentation des champs dans le tableau des efforts est décrite en détails à la rubrique Description du tableau de calcul des efforts.
      Barèmes de référence respectifs : DictionnaryColDelDiva ou DictionnaryColModifDiva.
      Facteur pris en compte : niveau de difficulté estimé dans la base Migration.
       

    • Champs masques.
      L'inventaire répertorie les champs de base dessinés dans un masque en surcharge ou en spécifique. A titre indicatif, le nombre d'utilisations est affiché dans le tableau des efforts.
      Un effort est estimé en cas de suppression ou de modification du champ par Divalto. L'estimation ne tient pas compte du nombre d'utilisations du champ.
      La présentation des champs dans le tableau des efforts est décrite en détails à la rubrique Description du tableau de calcul des efforts.
      Barèmes de référence respectifs : DictionnaryColDelForm ou DictionnaryColModifForm.
      Facteur pris en compte : niveau de difficulté estimé dans la base Migration.
       

  • Eléments forfaitaires.

    • Forfait migration.
      Une estimation forfaitaire valorise l'effort minimal à fournir pour initier et compléter toute migration (appel du choix de Xwin "Créer le projet de surcharge de la nouvelle version", migration des données, tests finaux, etc.).
      Barème de référence : MigrationPackage.
       

    • Moulinette de conversion des masques spécifiques en version 7.

      Une estimation forfaitaire valorise la mise en oeuvre de la moulinette de conversion des masques spécifiques de version 6 en version 7.
      Barème de référence : FormsConversionV6_V7.
      A titre indicatif, le nombre de masques à convertir est affiché dans la colonne "Nb masques à convertir" du tableau des efforts.

       

  • Eléments non inventoriés.

    • Menus.
      Voir la rubrique Migration des surcharges de menu.
       

  • Rappel des contraintes à respecter pour la constitution de l'inventaire.

    • Pour être inventoriés, il faut que les dictionnaires de surcharge soient inclus dans le répertoire Sources surcharge d'un sous-projet surchargé (ou dans un Groupe de sources de surcharge du projet).

    • Pour être inventoriés, il faut que les dictionnaires spécifiques soient inclus dans le répertoire Sources d'un sous-projet de surcharge (ou dans un Groupe de sources de surcharge du projet).

    • Pour que les zooms soient inventoriés, il faut que les fichiers a5f(u) soient en ligne lors de la constitution de l'inventaire.

    • Il faut que les fichiers de navigation soient créés et en ligne lors de la constitution de l'inventaire.

       

  • Autre contrainte

    • Pour qu'un Hfile soit traité correctement, le nom de l'instance doit être identique au nom du fichier dans le dictionnaire.
       

  • Restrictions.

    • Les groupes de sources utilisés en surcharge et supprimés dans l'ERP ne sont pas détectés.

    • Le changement de taille d'une table de l'ERP n'est pas traité.

    • Un source apparaissant plusieurs fois dans l'arbre du projet est inventorié plusieurs fois.

    • Les éventuels conflits de nom ne sont pas détectés.
      Par exemple, on ne vérifie pas qu'un objet spécifique porte le même nom qu'un nouvel objet de base de l'ERP ou qu'un objet de surcharge d'un dictionnaire porte le même nom qu’un nouvel objet du dictionnaire de base (en principe, les noms utilisés en surcharge sont codifiés pour ne pas créer de conflit avec les objets Divalto de base).

    • Dans un projet de surcharge, rien n'interdit de placer un source spécifique dans un sous-projet de base surchargé ou la surcharge d'un source de base dans un sous-projet spécifique. Le deuxième cas n'est pas correctement traité (les surcharges de sources de base doivent être placés dans les sous-projets surchargés).
