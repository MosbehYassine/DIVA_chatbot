Objet Rich-Edit

Les propriétés d'un objet Rich-Edit sont :
 

Famille Texte multi-lignes

Indices

S'il s'agit d'un élément de tableau Diva, précisez ses indices.

Mode

Indique si la donnée associée à l'objet contient le nom du fichier à éditer ou si elle contient le texte lui-même :

  • La donnée contient le texte
    Ce mode est intéressant si le texte n'est pas au format "texte enrichi", trop gourmand en espace mémoire. Dans ce cas, le programme doit, avant la première utilisation, initialiser la donnée à la valeur $00 (zéro binaire).

  • La donnée contient un nom de fichier
    Ce mode est conseillé pour les textes au format "texte enrichi". La donnée doit ici être garnie avec le nom du fichier contenant le texte. Le fichier doit être accessible par la gestion de fichiers d'Harmony.

Format 

Précise le format d'édition :

  • Rich-Text (fichier Windows d'extension .rtf) : format "texte enrichi".

  • Texte (fichier Windows .txt) : format "texte simple".

 

 

Famille Présentation

Largeur

Largeur, en millimètres, de la zone d'édition du document.
Cette largeur est indépendante de la taille de la boîte de l'objet (le cas échéant, un ascenseur horizontal est positionné dans la zone d'édition). Par exemple, la valeur 210 permet d'éditer un texte au format A4.

Famille Saisie : voir Paramètres de saisie.

Entrée en saisie au clavier

  • Non (valeur par défaut).
    Sauf si le texte riche est la seule variable en saisie de la page (auquel cas l'entrée en saisie est immédiate), le curseur ne s'y arrête pas lorsque l'utilisateur se déplace dans le masque uniquement au CLAVIER. Pour passer en saisie du texte riche, l'utilisateur doit cliquer avec la souris à l'intérieur de la zone d'édition.
    Le texte riche fait ici partie de l'ordre de saisie uniquement pour permettre à Ywpf de connaître la donnée "suivante", donnée sur laquelle il se place lorsque l'utilisateur valide ou abandonne la saisie du texte.
     

  • Oui.
    Le texte riche entre dans l'ordre de saisie comme n'importe quelle autre type de variable, avec toutefois une différence importante : Si les touches Tab ou Maj+Tab permettent d'entrer en saisie du texte lorsqu'elles sont tapées depuis la donnée précédente ou suivante dans l'ordre de saisie, ces mêmes touches ne permettent pas de quitter l'édition pour passer à la donnée suivante ou précédente car elles sont interprétées comme des touches de tabulation par l'éditeur de textes.

Attention :

  • On ne sait pas limiter le texte saisi par l’utilisateur. En mode « La donnée contient le texte », il en résulte un débordement possible par rapport à la capacité de la donnée réceptrice. Dans ce cas, Ywpf effectue une troncature et l’éventuel texte saisi excédentaire est perdu.

  • La taille des tabulations n’est pas identique à celle obtenue en Win32. Il en résulte qu’à l’impression (qui utilise l'interface Win32), on risque de ne pas obtenir le même rendu qu’à l’affichage.
