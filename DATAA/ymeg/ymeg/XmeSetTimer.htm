XmeSetTimer  Famille Thème

Lancement ou arrêt d'un "timer" en consultation de masque

 

XmeSetTimer (Délai, Code, Shift, Ctrl)

 

Paramètres :

Délai

Valeur du délai en secondes ou 0 pour stopper le timer.
Valeur par défaut : 0.

Code

Code (Harmony.Key) du caractère à simuler (type X).
Voir aussi le paragraphe "Compatibilité avec la version 5 d'Harmony" ci-après.

Shift

Valeur à placer dans la donnée ShiftKey au retour dans le programme appelant (TRUE ou FALSE). Valeur par défaut : FALSE.
Obsolète à partir de la version 6 (et ignoré si Code > 256 : voir le paragraphe "Compatibilité avec la version 5 d'Harmony" ci-après).

Ctrl

Valeur à placer dans la donnée ControlKey au retour dans le programme appelant (TRUE ou FALSE). Valeur par défaut : FALSE.
Obsolète à partir de la version 6 (et ignoré si Code > 256 : voir le paragraphe "Compatibilité avec la version 5 d'Harmony" ci-après).

 

Description de la fonction :

  • Un délai peut être associé aux fonctions XmeConsult et XmeListConsult, de manière à ce que celles-ci rendent la main au programme appelant à intervalles réguliers et ce, même si l'utilisateur ne produit aucun événement clavier ou souris. Ceci permet par exemple d'actualiser régulièrement l'écran sans intervention de l'utilisateur.

  • Lorsqu'un tel délai est lancé, le système simule une entrée clavier de la part de l'utilisateur à intervalles de temps réguliers. Le code (Harmony.Key) du caractère à simuler doit être précisé dans le paramètre Code de XmeSetTimer.

  • Pour mettre un délai en route (avant d'appeler XmeConsult ou XmeListConsult), faites appel à XmeSetTimer en précisant dans le paramètre Délai l'intervalle de temps (en secondes) qui devra séparer deux simulations de touche.
    Pour stopper le délai, appelez XmeSetTimer sans paramètre ou avec le paramètre Délai à 0.

  • Si vous lancez successivement plusieurs timers, ceux-ci sont "empilés" par le système. Attention donc à stopper tous les timers lancés.

 

Compatibilité avec la version 5 d'Harmony :

En version 5, le paramètre Code représentait le code PC8 (Cf. defines F_XXXX de Zdiva) de la touche à simuler et les paramètres Shift et Ctrl permettaient de simuler la frappe combinée de certaines touches particulières avec Shift et/ou Ctrl.

La compatibilité entre version 5 et versions ultérieures est assurée car le système sait différencier un ancien code PC8 (valeur < 256) d'un nouveau code Harmony.Key (valeur > 256). Le seul cas d'incompatibilité (plus qu'improbable) surviendrait si en version 5, le programme simulait une touche (accentuée) n'ayant pas le même code en PC8 et en ANSI (les fonctions XmeConsult, etc. renvoyant maintenant le code ANSI de la touche et non plus le code PC8).

 

 

Exemple :

XmeSetTimer (10,K_F16)                          ;lancement d'un délai de 10 sec.

                                                ;F16 simulée

Fini = FALSE

DO

   XmeConsult ("MASQUE",1,XME_MODE_GOTO) 

                                                ;consultation de la page 1 

                                                ;du fichier masque "MASQUE" 

   SWITCH Harmony.Key

      CASE K_ESCAPE                             ;fin 

         Fini = TRUE

 

      CASE K_F16                                ;caractère simulé 

         RafraichissementEcran

 

      ...                                       ;etc. 

   ENDSWITCH 

WHILE Fini = FALSE

WEND

 

XmeSetTimer ()                                  ;arrêt du timer

 

Autre exemple :

 

XmeSetTimer (5,K_CTRL_SINSERT)                  ;timer de 5 secondes

                                                ;Ctrl+Shift+Inser simulé
