XmeListScreenCountAsync  Famille Thème

Lecture "asynchrone" du nombre de lignes d'un tableau

 
Long XmeListScreenCountAsync (Identifiant)

 
Paramètre :

Identifiant

Identificateur du tableau rendu par la fonction XmeListGetId.

 

Valeur rendue par la fonction :

  • Si le tableau est à l'écran, la fonction renvoie le nombre de lignes actuellement affichées.

  • Si le tableau n'est pas à l'écran, la fonction renvoie le nombre de lignes présentes à l'écran lors du dernier affichage du tableau (nombre lu dans la base de registre).

  • Si le tableau n'a jamais été affiché (lorsque la base de registre ne contient pas ou plus l'information), la fonction renvoie un nombre de lignes approximatif basé sur le dessin du tableau dans Xwin.

 
Description de la fonction :

  • La fonction XmeListScreenCountAsync doit être utilisé dans le seul but d'accélérer le chargement et l'affichage initial d'un objet tableau (Cf. rubriques Affichage et exécution d'un traitement Diva simultanés et XmeFlushAsync).
     

  • Elle présente les différences suivantes par rapport à la fonction XmeListScreenCount :
     

    • XmeListScreenCount ne peut être appelée que si la page de masque affichant le tableau est la page courante (ou une de ses pages panels). Elle délivre toujours le nombre exact de lignes visibles du tableau.

      XmeListScreenCountAsync peut être appelée si le tableau n'est pas présent à l'écran ou alors que la page de masque affichant le tableau n'est pas la page courante. Elle permet d'avoir une idée approximative du nombre de lignes qui seront visibles lorsque le tableau sera affiché à l'écran.
       

    • Après l'affichage de la page contenant le tableau par le programme Diva, la fonction XmeListScreenCount interroge le client pour connaître le nombre exact de lignes visibles. Le client ne peut répondre à cette question qu'après avoir "physiquement" affiché le tableau. Il en résulte une interruption de l'asynchronisme entre XrtDiva et le client, dont l'exécution respective redevient séquentielle.

      XmeListScreenCountAsync n'interroge jamais le client mais lit le "dernier" nombre de lignes visibles dans la base de registre. Elle ne rompt donc pas l'asynchronisme entre XrtDiva et le client dont l'exécution respective peut se poursuivre en parallèle.
       

    • Mais attention, il n'est en aucun cas garanti que le nombre rendu par XmeListScreenCountAsync corresponde exactement au nombre de lignes visibles au prochain affichage du tableau (même s'il s'agira du nombre exact dans la plupart des cas). Il est donc impératif d'appeler ensuite XmeListScreenCount pour garnir correctement le tableau (voir l'exemple).

 

Exemple :

Cet exemple est calqué sur le cas du programme Diva xZoom. Au chargement du Zoom, celui-ci exécute une requête SQL pour lire les informations destinées à garnir le tableau du mode liste. En effectuant cette lecture en parallèle avec l'affichage du masque du zoom, il en résulte une accélération du chargement initial.

 

 

1. Exécution "synchrone" :

XmeLoad  ...

...

XmeDispv ...                          ;affichage de la page contenant le tableau

NbLig = XmeListScreenCount (Id)       ;récupération du nb exact de lignes visibles
GarnirTableau (NbLig)                 ;lecture des informations

 

XmeListConsult (Id)                   ;consultation du tableau

 

 

2. Exécution "asynchrone" :

 

XmeLoad  ...

...

XmeDispv ...                          ;affichage "logique" de la page contenant le tableau

XmeFlushAsync                         ;lancement de l'affichage "physique"

NbLig = XmeListScreenCountAsync (Id)  ;nb de lignes théoriquement visibles

GarnirTableau (NbLig)                 ;pré-lecture des informations en parallèle

 

NbLig = XmeListScreenCount (Id)       ;récupération du nb exact de lignes visibles
AjusterTableau (NbLig)                ;ajustement entre nb de lignes théoriques et réels

 

XmeListConsult (Id)                   ;consultation du tableau
