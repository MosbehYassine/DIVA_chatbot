Positionnements souris en saisie de masque

Dans cette rubrique, nous allons nous intéresser aux déplacements, effectués par l'utilisateur à la souris, lors de la saisie d'un masque (fonction XmeInput) ou d'une ligne de tableau (fonction XmeListInput).

 

1. Déplacements souris en saisie d'une page de masque Xwin "isolée".

Ces déplacements sont gérés par Ywpf de manière transparente pour les programmes : si l'utilisateur clique sur une donnée B de la page X depuis une donnée A de la même page X, le focus est automatiquement transféré sur la donnée B (sous certaines réserves toutefois : variable A obligatoire non renseignée ; refus de ce positionnement par un traitement ou arrêt -APRES saisie de la donnée A et AVANT saisie de la donnée B-).
 
L'exemple suivant montre une telle saisie de page :
 

+--------------------------------------------+

| Code client          : ........ <--+--+    |

|                                    |  |    |

| Numéro de facture    : ........ <--+  |    | Page de masque Xwin

|                                    |  |    |

| Adresse de livraison : ........ <--+--+    |

+--------------------------------------------+

<-- Positionnements traités par Ywpf en interne

 
Si l'utilisateur clique depuis n'importe quelle donnée sur n'importe quelle autre donnée de la même page, le déplacement du curseur sur la donnée cliquée est automatique et ne demande aucune programmation particulière.

Il en est de même en saisie d'une ligne de tableau, si l'utilisateur clique sur une donnée de la même ligne.
 

 

2. Déplacements souris inter-page.

Il n'en est plus ainsi si l'écran affiche simultanément plusieurs pages de masque Xwin.
Ywpf ne peut se charger des positionnements souris qu'à l'intérieur de la page en cours de saisie car il faut avertir le programme appelant afin que celui-ci termine la saisie en cours et commande lui-même la saisie de la nouvelle page.
 

Si l'utilisateur clique sur une donnée B de la page Y depuis une donnée A d'une autre page X, le clic restera donc inopérant sans programmation complémentaire. Il en sera de même en saisie d'une ligne de tableau, si l'utilisateur clique sur une donnée d'une autre ligne.
 
Illustrons ceci par l'exemple d'un écran de type facturation présentant un en-tête, un tableau de lignes détail et un pied.
L'en-tête et le pied sont dessinés dans deux pages Xwin différentes (l'objet Tableau ne nous intéresse pas ici) :
 

+------------------------------------+ <--+

| Code client       : ........       |    |

| Numéro de facture : ........       |    | Page "En-tête"

| ...                                |    |

+------------------------------------+ <--+

                   ...

                   ...

+------------------------------------+ <--+

| Tva               : ........       |    |

| Total             : ........       |    | Page "Pied"

| ...                                |    |

+------------------------------------+ <--+

 
De manière automatique, Ywpf ne permet pas de se déplacer à la souris de l'en-tête vers le pied et réciproquement du pied vers l'en-tête car il s'agit de pages Xwin différentes :
 

+------------------------------------+

| Code client       : ........       |

| Numéro de facture : ........       |<-------+

| ...                                |        |

+------------------------------------+        |

                   ...                        |

                   ...                        |

+------------------------------------+        |

| Tva               : ........       |        |

| Total             : ........       |<-------+

| ...                                |

+------------------------------------+

<-- Positionnements non traités par Ywpf en interne

 

Les positionnements souris inter-page restent cependant programmables en utilisant les points d'arrêt "Demande de saisie".

Dans l'exemple, l'utilisateur pourra passer d'une donnée en saisie dans l'en-tête (respectivement le pied) vers une donnée en saisie dans le pied (respectivement l'en-tête) grâce à ce type de point d'arrêt.
