Notion de projet et sous-projet

L'atelier de développement d'Harmony a pour base la notion de projet.

L'utilisation des projets apporte au développeur les avantages suivants :

  • une gestion simplifiée des fichiers sources

  • la recompilation automatique des sources en fonction des modifications effectuées (calcul des dépendances entre les modules, entre les sources et les includes, entre les sources et les dictionnaires)

  • la possibilité de naviguer dans les sources (recherche de la définition d'une fonction, recherche de toutes les utilisations d'une donnée, etc.)

 

Qu'est ce qu'un projet ?

Un projet représente une application complète. Par exemple, Divalto Achat-Vente est un projet, Divalto Comptabilité est un autre projet.

Un projet est donc une entité de grande taille. En effet, Divalto Achat-Vente est composé de plusieurs centaines de programmes.

Pour ne pas travailler au niveau d'une entité aussi volumineuse, le programmeur découpera un projet en plusieurs sous-projets.

 

Qu'est ce qu'un sous-projet ?

Un sous-projet est donc un sous ensemble du projet. Pour simplifier, nous pouvons dire qu'un sous-projet correspond à un choix du menu.

Par exemple, le programme de saisie de commandes de Divalto Achat-Vente est un sous-projet qui comporte un programme Diva, un masque écran, plusieurs modules de traitement etc.

Un autre exemple de projet est un module de fonctions qui est utilisé dans plusieurs programmes. Un tel module fait l'objet d'un sous-projet.

La définition du contenu d'un sous-projet est entièrement libre. Le développeur peut y inclure les éléments sur lesquels il désire travailler à un moment donné.

 

Surcharge des projets

Les projets peuvent être surchargés.

La surcharge des projets est utilisée lors de la verticalisation d'applications. Par exemple, Divalto livre un projet pour Divalto Achats-Ventes. Le développeur qui rajoute des nouvelles fonctionnalités (nouveaux sources, nouvelles fonctions etc.) peut alors rajouter ses fichiers dans le projet, naviguer dans ses sources et dans les sources fournis par Divalto. Ces modifications sont stockées dans d'autres fichiers projets que les fichiers fournis par Divalto. Ainsi, lors du passage à une nouvelle version (installation du projet modifié par Divalto) les modifications ne sont pas écrasées.
