Suivi des informations de couverture du code

 

Pour chaque source concerné, Xwin assure le suivi des informations de couverture remontées par le débogueur :

  • Toute modification effectuée à l'intérieur d'une ligne de source annule les informations de couverture concernant la totalité de la ligne (elle est entièrement décoloriée). Le cas échéant, la commande Annuler restaure la coloration initiale.

    Cas particulier d'une instruction Diva éclatée sur plusieurs lignes ("\") : Seule les lignes effectivement modifiées sont décoloriées, les autres lignes de l'instruction restent inchangées ; si vous le souhaitez, vous pouvez manuellement décolorier la totalité de l'instruction grâce à la commande "Marquer la sélection comme non couverte".

     

  • Le choix Marquer la sélection comme non couverte du sous-menu Couverture du code (menu Déboguer ou menu contextuel de l'éditeur de textes) permet d'effacer la couverture courante pour l'ensemble des lignes sélectionnées du source actif (ces lignes sont décoloriées).

    Cette commande peut servir par exemple à "réinitialiser" un bloc de lignes complet, suite à la modification d'une ligne remettant en cause l'algorithme d'exécution de l'ensemble.

    Remarques     :

    • Cette opération est considérée comme une modification du source avec toutes les implications que cela comporte (montée de l'* de modification dans la barre de titre de la fenêtre, application possible des commandes Annuler et Recommencer, enregistrement définitif à la sauvegarde du source, etc.). En particulier, comme la trace est automatiquement interrompue lorsqu'un source du sous-projet est modifié, cette commande est interdite en cours de débogage (afin de ne pas interrompre la trace ipso facto).

    • Cette commande nécessite que le mode "Colorier les lignes couvertes" soit actif. Dans le cas contraire, le choix correspondant du menu est grisé.
      Attention       : si vous avez validé l'option de Xwin "Activer / Désactiver automatiquement la colorisation des lignes couvertes en Début / Fin de session de débogage", le choix du menu est toujours grisé (en cours de débogage, parce que la commande y est interdite ; hors débogage, parce que le mode "Colorier les lignes couvertes" n'est pas actif) !! Pour dégriser le choix, il vous faudra d'abord rétablir le mode "Colorier les lignes couvertes".
       

     

  • Les informations sont mémorisées et stockées dans un fichier des couvertures.
    Le nom de ce fichier est déduit du nom du fichier source en remplaçant le suffixe .dhsX par _dhsX.dhcc (exemple : fic.dhsp --> fic_dhsp.dhcc).

    Les fichiers des couvertures sont rangés dans un répertoire spécifique, paramétré au niveau du profil (Cf. rubrique Configuration de la couverture du code).

    Le bouton Nettoyer, également présent dans la boîte des propriétés du profil, permet de supprimer tous les fichiers (.dhcc) contenus par ce répertoire (mais attention, cette opération supprime aussi toutes les informations de couverture courantes).

    Le choix Effacer la couverture du fichier courant du sous-menu Couverture du code (menu Déboguer ou menu contextuel de l'éditeur de textes) permet d'effacer les informations courantes du source actif et de supprimer le fichier des couvertures associé. Le choix Effacer la couverture de tous les fichiers du sous-projet courant effectue la même opération mais cette fois pour tous les sources concernés du sous-projet actif.

    Une option de Xwin demande aussi que toutes les informations de couverture soit effacées à chaque nouvelle exécution de l'application (Cf. rubrique Configuration de la couverture du code).



    REMARQUE     IMPORTANTE :

    Il faut bien comprendre que le fichier des couvertures doit rester parfaitement synchrone avec son source associé. Dans le cas contraire, les informations enregistrées dans le fichier par exemple pour la ligne N1 du source risqueraient d'être appliquées à une ligne N2 différente de N1, rendant celles-ci totalement obsolètes.
    Xwin garantit cette synchronisation autant que faire ce peut (voir la rubrique Interruption de la trace des instructions exécutées).

    Vous devez toutefois respecter les contraintes suivantes     pour ne pas "casser" un fichier des couvertures :

    Ne pas modifier le source en dehors de l'éditeur Xwin    .
    Ne pas modifier le source d'un masque ou d'un dictionnaire chargé en mode Texte    .
    Ne pas modifier la taille des tabulations     (ceci risque de casser les couvertures partielles).

    Attention : de plus, Xwin ne gère pas le partage des informations de couverture par plusieurs utilisateurs.

    La date de dernière modification du source est enregistré dans le fichier des couvertures afin que Xwin puisse détecter que les deux fichiers sont désynchronisés. Le cas échéant, Xwin signale l'anomalie, ignore les informations contenues par le fichier des couvertures et renomme ce fichier (l'extension .dhcc est remplacée par .bak.dhcc).

 

Remarque : Si la trace des instructions exécutées ne s'applique qu'aux sources du sous-projet actif compilés en mode "Couverture du code", Xwin assure le suivi de tous les sources faisant l'objet d'une couverture (ceux pour lesquels un fichier des couvertures est enregistré).
