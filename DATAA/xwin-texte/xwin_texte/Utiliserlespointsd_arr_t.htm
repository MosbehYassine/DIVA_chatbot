Utiliser les points d'arrêt

 

Les points d'arrêt indiquent au débogueur où ou quand interrompre l'exécution d'un programme. L'interruption consiste en un arrêt temporaire, durant lequel vous pouvez examiner l'état de votre programme, consulter ou modifier ses variables, visualiser la pile, rejouer l'historique, etc.

Nota : Vous pouvez poser jusqu'à 100 points d'arrêt.

 

Il existe sept types de point d'arrêt :

  • Arrêt sur ligne : le programme s'interrompt, sans autre condition, juste avant que le débogueur n'exécute l'instruction située sur la ligne marquée par le point d'arrêt.

  • Arrêt sur ligne si expression vraie : comme précédemment, le programme s'interrompt avant que le débogueur n'exécute l'instruction marquée par le point d'arrêt. Toutefois, l'interruption n'aura lieu que si une certaine expression en mémoire est vraie.

  • Arrêt sur ligne si expression change : arrêt similaire au cas précédent mais cette fois, l'interruption n'aura lieu que si une certaine expression en mémoire a changé de valeur.

  • Arrêt si expression vraie : le programme s'interrompt dès qu'une certaine expression en mémoire passe à vraie.

  • Arrêt si expression change : le programme s'interrompt dès qu'une certaine expression en mémoire change de valeur.

  • Arrêt si attribut dynamique change : le programme s'interrompt dès que la valeur d’un attribut dynamique est modifiée (fonctions Diva XmeSetAttribut et XmeResetAttribut).

  • Arrêt si attribut dynamique ligne change : le programme s'interrompt dès que la valeur d’un attribut dynamique « tableau » est modifiée (fonctions Diva XmeListSetAttribut et XmeListResetAttribut).

 

Utilisez par exemple le point d'arrêt sur ligne lorsque vous avez une idée approximative du lieu où votre programme pose problème. Le débogueur exécute le programme jusqu'à rencontre du point d'arrêt. A partir de là, vous pouvez utiliser les commandes du mode " pas à pas " pour dérouler le programme jusqu'à ce que vous repériez précisément les instructions ayant un comportement anormal.

Les points d'arrêt sur expression sont plus rarement utilisés mais ils sont très pratiques, par exemple dans le cas suivant : vous savez que votre programme modifie la valeur d'une donnée de manière anormale mais vous ne savez pas à quel endroit. Le point d'arrêt sur ligne et le mode pas à pas sont ici peu efficaces pour repérer l'instruction en cause. Le point d'arrêt si expression change est par contre parfaitement adapté à cette situation.

 

Le bouton ("Poser / Annuler un point d'arrêt") de la barre d'outils de l'éditeur de textes permet la pose (ou l'effacement) d'un point d'arrêt simple sur la ligne courante du source actif (fonction également disponible au menu, au clavier ou à la souris). La boîte de dialogue "Points d'arrêt" permet la pose de points d'arrêt plus complexes, comme ceux demandant l'interruption du programme si une expression change ou devient vraie.

Des points d'arrêt peuvent être posés dans le programme principal, les includes, les modules, les traitements de dictionnaire ou de masque. La boîte de dialogue "Points d'arrêt" maintient une liste de tous les points d'arrêt définis.

 

Les points d'arrêt sur ligne sont signalés au niveau des sources par une icone de forme circulaire affichée en marge des lignes concernées.

 

Les points d'arrêt que vous avez posé sont mémorisés lorsque vous quittez Xwin ; ils redeviennent actifs lorsque Xwin est rouvert.
