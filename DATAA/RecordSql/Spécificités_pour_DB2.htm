Spécificités pour DB2

 

Le RecordSql possède déjà quelques syntaxes génériques pour assurer, au moment de l'exécution, une compatibilité avec les bases SQL Server et IBM DB2.

 

Seulement, dans certains cas, il n'est pas possible d'avoir une syntaxe commune.

 

On a donc introduit une "exécution conditionnelle" des RecordSql. Cela veut dire que, suivant le type de la base de données, ce n'est pas le même RecordSql qui sera exécuté.

 

Au niveau programmation dans le langage Diva, rien ne change.

 

Dans les dictionnaires de RecordSql, il y a une nouvelle structure de contrôle :

 

#if_db2

Code SQL spécifique DB2

#default

Code SQL spécifique SQL Server

#end

 

Dans le cas particulier de la balise <Select>, la structure est :

 

#if_db2

Code spécifique DB2 \

#default

Code spécifique SQL Server \

#end

as nomChamp (typechamp)

 

 

 

Cette structure de contrôle est utilisable dans toutes les balises du RecordSql.

 

Attention : les balises #if_db2, #default et #end DOIVENT être en colonne 1.

 

Contraintes :

  • Si utilisé dans le chapitre <Select>, il ne faut pas mettre plus d'un champ par structure de contrôle

  • Si utilisé dans le chapitre <Select>, le type du champ doit se situé après la balise #end

  • Si utilisé dans le chapitre <Select>, chaque ligne doit se terminé par le caractère \

  • Si utilisation d'un #if_db2, la partie #default est obligatoire, ainsi que le #end

 

Exemple tiré du dictionnaire wmrsvtl.dhsq :

 

<RecordSql Name=ZWMVTL Comment='Ventilation WMS' zoomoptimize = yes>

<SELECT>

WMVTL.*

...

#IF_DB2

;le IN SUBQUERY ne fonctionne pas en DB2

' ' \

#DEFAULT

CASE WHEN WMVTL.LIEU IN SUBQUERY(WM_Transit) THEN 'T' ELSE '' END \

#END

as Transit (>WMSFDD.DHSD ce1) name = 'WMVTL'

 

<FROM Insert=Yes Update=Yes Delete=Yes>

WMVTL
