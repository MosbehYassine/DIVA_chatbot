Join LeftJoin RightJoin FullJoin CrossJoin   Famille  Thème

 

Ces balises servent à définir les jointures vers d’autres tables. Elles correspondent aux différents types de jointure qui existent en SQL.

On trouvera donc :

<Join> pour le inner join de SQL,

<LeftJoin> pour le left join de SQL,

<RightJoin> pour le right join de SQL,

<FullJoin> pour le full join de SQL,

<CrossJoin> pour le cross join de SQL.

 

De plus, il existe la balise <Join01>, avec exactement la même syntaxe qu’une balise <Join>, mais qui ne correspond pas à une jointure SQL.

 

Syntaxe :

 

<xxxJoin [ Database="value" ]  [ GlobalConf={ yes | no }  ]  [ Name="value" ] [ ColumnNames="values" ] [ Dependencies="values" ] [ NoActivate ] [ NoCheck ] [WithId]>

[ DictionaryName ] table [ as uniqueAlias ]

[Case variante]

ON conditionDeJointure

  • Name : Noms de la jointure, séparés par des points-virgules.

  • Dependencies : Noms des jointures dépendantes, séparés par des points-virgules.

  • ColumnNames : Noms des champs pour faire le lien avec les champs du Select, séparés par des points-virgules.

  • NoActivate : Indique que cette jointure sera désactivée par défaut.

  • NoCheck : Demande que XRecordSQLCheck ne vérifie pas que cette jointure utilise des colonnes correspondant à un index de la table jointe.

  • WithId : Un champ table_Id est ajouté aux champs calculés du RecordSql. Ce champ contient l'Id de la ligne jointe.

  • Case : permet de définir des variantes de la condition

 

Une jointure contient :

• Le nom de la table, sous la forme (voir la balise <From>) :

[DictionaryName] table [as uniqueAlias]   (voir les remarques sur les alias)

• L’expression SQL de la jointure entre les tables. Cette expression commence par le mot-clé Sql ON.

 

Exemple de jointure « simple » :

<LeftJOIN>

STC as STC

ON STC.Dos = CLI.Dos And STC.TiCod = 'C' And STC.Tiers = CLI.Tiers

 

Exemple de jointure conditionnelle :

En fonction du paramétrage, jointure vers la table commune ou vers la table du dossier.

<LeftJOIN>

   T001 as LibFamTarif

   ON LibFamTarif.CeBin = 1 AND LibFamTarif.TiCod = 'C' AND LibFamTarif.TaFam = CLI.TaFam

      AND LibFamTarif.Dos = CASE WHEN T000.TabTyp(1) = 2 THEN 999 ELSE MZ.Dos END

 

 

Confidentialités

Par défaut, si l'utilisateur ne dispose pas des droits pour accéder à une table liée, les champs de cette table liée sont mis à espace mais la ligne lue dans la table de base est tout de même délivrée.

L'attribut GlobalConf= {yes|no} fait remonter au niveau principal le fait que l'utilisateur ne dispose pas des droits. Autrement dit, si l'utilisateur n'a pas les droits pour lire une table liée marquée GlobalConf=yes, la ligne de la table principale est masquée pour cet utilisateur.

 

Jointure dynamique

Il peut être intéressant de désactiver momentanément une ou plusieurs jointures. Pour cela, il faut les nommer et utiliser les instructions RecordSql.Join.Activate et RecordSql.Join.Deactivate.

L'attribut Name=value permet de donner un ou plusieurs noms à une jointure. Les différents noms doivent être séparés par le caractère ; (point-virgule).

Par défaut, toutes les jointures possèdent un nom qui correspond au nom de la table (ou de l'alias).

 

L'attribut "ColumnNames"

Dans les champs du Select, il est possible d'associer un "Name" aux expressions. Ce "Name" correspond à un "ColumnName" de jointure. Une jointure peut avoir plusieurs "ColumnNames" (noms séparés par un point-virgule).

Ce lien est utilisé par le zoom pour désactiver les jointures qui deviennent inutiles lorsque des champs sont retirés du Select.

 

L'attribut "Dependencies"

Cet attribut permet de définir des dépendances entre les jointures. Une jointure doit en effet déclarer les autres jointures qui doivent obligatoirement être activées si elle-même est active.

Pour déclarer une dépendance, il convient de renseigner l'attribut "Dependencies" avec le nom de la table de jointure utilisée en dépendance. Si cette table possède un alias, c'est cet alias qu'il faut utiliser.

Une jointure peut avoir plusieurs dépendances. Dans ce cas, il convient de séparer les différents noms par un point-virgule.

 

Champ Id

Le compilateur génère un champ correspondant à l'identifiant de la ligne lue dans la table (version cible du profil supérieure ou égale à 7.5).

Ce champ est visible en Diva, sous le nom alias_table_ID.

 

Variantes

Il est possible pour une même jointure d'avoir plusieurs ON ou USING, chacun étant appelé une Variante.

Le RecordSql doit être noactivate pour autoriser les variantes.

La version cible du compilateur doit être supérieure à 2023-410a.

Pour sélectionner une variante, il faut utiliser l'instruction Join.ActivateCase.qui active la jointure et sélectionne la variante désirée.

Attention : si la jointure est activée par Join.Activate il faut impérativement sélectionner la variante, sinon il y aura une erreur lors de l'exécution de la requête.

 

Exemple :

 

<Select>

ART.*

ClientImportant.Nom

COALESCE(Chemin1.Chemin, Chemin2.Chemin) as CheminConfigurateur (>A5DD.dhsd Chemin) Name="chemin"

<From>

gtfdd.dhsd ART

<LeftJoin Name="Zoom">

gtfdd.dhsd STB as STB

ON ...

<LeftJoin Name="Zoom" Dependencies="STB">

gtfdd.dhsd CLI as ClientImportant

ON STB.TIERS = ClientImportant.Tiers

<LeftJoin Name="Zoom" ColumnNames="chemin">

A5DD.dhsd MCHEMIN as Chemin1

ON ...

<LeftJoin Name="Zoom" ColumnNames="chemin">

A5DD.dhsd MCHEMIN as Chemin2

ON ...

 

Dans cet exemple, l'activation du champ "ClientImportant.Nom" va déclencher l'activation de la jointure "CLI", qui elle-même va déclencher ses dépendances, à savoir "STB".

L'activation du champ "CheminConfigurateur" va déclencher l'activation des jointures dont le Name="chemin" est contenu dans la liste "ColumnNames", à savoir "Chemin1" et "Chemin2".
