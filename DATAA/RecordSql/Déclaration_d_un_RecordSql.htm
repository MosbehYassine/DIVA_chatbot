Déclaration d'un RecordSql

 

La déclaration d'un RecordSql est similaire à la déclaration d’un Record.

 

[public | protected | extern ] RecordSql [KeepDataNames] dico mnémo [Instance]

 

Public

Spécifie que la variable var est publique. Si plusieurs modules déclarent la même variable publique, elle est allouée une seule fois à l'exécution.

Protected

Spécifie que la variable var est protégée. Une nouvelle instance est allouée.

Extern

Voir Extern

KeepDataNames

Voir  Record.

Dico

Nom du dictionnaire de RecordSql.

Mnémo

Nom du RecordSql.

Instance

Si ce paramètre n'est pas spécifié, le nom de l'instance est le nom du RecordSql.

 

L’accès aux données de l’instance du RecordSQL s’effectue de la même manière que l’accès aux données d’un Record, grâce à la notation pointée.

 

Exemple

Public RecordSql 'GTRSTIERS.dhoq' CLIENT

Client.Tiers est le champ Tiers

Client.Adr est le champ Adresse

 

Remarques

Sur-champs et sous-champs

Dans la table de la base de données, seuls existent les champs définis dans le dictionnaire de données comme « Non masqué pour SQL ». Par contre, les sur-champs (comme par exemple Client.adr) ou les sous-champs (comme par exemple Client.Dep, sous-champ de Client.Cpostal) sont bien utilisables en Diva ou dans un masque. Un sur-champ n'est utilisable que si tous ses sous-champs sont présents dans la balise Select.

Champs tableaux

Les tableaux n’existent pas dans une base de données SQL. A la création de la table, un tableau est remplacé par autant de colonnes qu’il y a de cellules dans le tableau. Par contre, la notation indicée reste possible en Diva ou dans un masque. L’indice peut-être une variable, à condition que toutes les cellules du tableau soient présentes dans le RecordSQL.

Structures Diva

Un RecordSql ne peut pas être déclaré dans une structure Diva.
