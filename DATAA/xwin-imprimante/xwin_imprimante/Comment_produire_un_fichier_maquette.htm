Comment produire un fichier maquette

 

La constitution d'une maquette pour un état imprimé s'obtient en lançant le programme à l'origine de l'état souhaité, après avoir spécifié l'utilisation d'un modèle d'imprimante demandant la génération d'une maquette :

  • Créez un modèle d'imprimante avec le Type d'imprimante "Maquette" et sélectionnez-le.
    Toute édition effectuée avec ce modèle générera un fichier maquette qui pourra ensuite être rejoué indépendamment du programme ayant produit cette édition (voir la rubrique Comment imprimer une maquette).

    La gestion des modèles et la méthode pour sélectionner un modèle donné sont expliquées dans le livre Impressions du manuel de référence d'Harmony (voir en particulier les rubriques Configuration des éditions et Gestion des modèles d'imprimante).
     

  • Lancez votre programme d'impression.
    Un fichier maquette est généré, portant le nom du masque imprimante suffixé par "_" et d'extension .xml.

    Exemple     : Si le programme utilise le masque MonMasque.dhoi, le fichier généré portera le nom MonMasque_.xml.

    Remarque     :
    Lorsque le fichier n'existe pas, il est créé au premier xmiPrint.
    Si le programme charge plusieurs masques, le fichier maquette portera le nom du masque faisant l'objet du premier xmiPrint (voir le paragraphe "Restriction lorsque le programme de constitution de la maquette charge plusieurs masques" à la fin de cette rubrique).
     

  • Pour générer plusieurs maquettes à partir du même masque d'impression.
    Par défaut, un fichier maquette unique est associé à chaque masque d'impression et l'ancien contenu du fichier xml est écrasé chaque fois que le programme est exécuté.

    Si vous souhaitez produire plusieurs maquettes à partir d'un même masque (obtenues par exemple pour différents jeux de données ou différentes options du programme), activez l'option du modèle Suffixer le nom du fichier maquette avec la date.

    Dans ce cas, un nouveau fichier est généré à chaque exécution du programme d'impression, portant le nom du masque suffixé par "_" suivi de la date et de l'heure de l'édition.

    Exemple     : MonMasque_20160308_1726.xml.
     

  • Pour faciliter l'identification d'une maquette par un utilisateur.
    Une maquette peut être imprimée par un utilisateur depuis l'Assistant de personnalisation des masques d'impression. Si plusieurs maquettes existent pour un masque donné, l'assistant affiche la liste de ces maquettes et propose à l'utilisateur de choisir la maquette qu'il désire dans cette liste. Il est donc important de lui faciliter la tâche en identifiant chaque maquette le plus clairement possible.

    Dans ce but, l'assistant affiche deux renseignements que vous pouvez personnaliser :
     

    • Le nom du fichier maquette.
      Vous pouvez changer le nom du fichier, afin de le rendre "compréhensible".

      Mais attention, il est impératif que le nom du fichier reste préfixé par le nom du masque suivi de "_" et conserve l'extension .xml.

      Exemples       avec le masque MaPiece.dhoi : MaPiece_Devis.xml ; MaPiece_Facture.xml.
       

    • Le libellé de la maquette.
      Ce libellé est recherché dans l'attribut "libelle" de la balise <report> du fichier xml (deuxième ligne du contenu du fichier).

      Cet attribut est initialisé à espace à la 1ère constitution de la maquette. Vous pouvez ensuite le garnir manuellement à votre convenance (256 caractères maximum).

      Exemples       : <report libelle="Devis" ... ; <report libelle="Facture" ...
       

Remarque importante concernant l'affichage de ces renseignements en langue étrangère :

  • Le nom du fichier personnalisé n'est évidemment pas traduit.
    Le cas échéant, il peut être copié sous un autre nom (dans la langue souhaité) ou créé immédiatement en langue anglaise.
    En cas de changement de nom, attention à conserver le préfixe initial.
     

  • Le libellé fait l'objet d'une traduction "Diva", recherchée dans le dictionnaire "Divalto".
    Il convient donc d'injecter les libellés des maquettes dans un fichier dictionnaire de référence et de les traduire dans la langue souhaitée.

    La méthode suivante pourra être utilisée pour injecter les libellés dans le fichier dictionnaire de référence :

    • Développeur de l'ERP Divalto.
      Placer les libellés des maquettes dans un fichier spécifique (par exemple : LibellesMaquettes.txt).
      Ajouter le nom de ce fichier à la liste des fichiers à traiter lors de l'injection. L'ajout se fait dans le "Fichier paramètres complémentaire", sous la balise <Fichier> (par exemple : <Fichier>LibellesMaquettes.txt).

    • Développeur d'une surcharge de l'ERP Divalto (ou d'une application spécifique).
      La méthode est identique, à ceci près que l'injection doit être faite dans votre fichier dictionnaire de surcharge (ou spécifique).
      Le fichier dictionnaire contenant les traductions doit être ajouté, dans le fichier paramètres TranslateParams.txt, à la liste des fichiers du dictionnaire Divalto. Par exemple :
      <Dictionnary>Divalto
      <Language>EN
      <File>InfinityLangue_en.dhot
      <File>MonDictionnaire_en.dhot

Pour tous les détails, se reporter à la rubrique "Création d'un dictionnaire de référence" du livre "Traduction" du manuel de référence d'Harmony.

 

Les fichiers maquette sont stockés dans le sous-dossier "Maquettes" du dossier pointé par la clé ServeurXlogf du chapitre System de la base de registre (/Divalto/Sys/Maquettes par défaut). Le lieu de stockage dépend donc de l'environnement choisi.

 

 

Restriction lorsque le programme de constitution de la maquette charge plusieurs masques

Comme nous l'avons vu précédemment, le nom du fichier xml créé à la constitution d'une maquette est calculé à partir du nom du masque ayant fait l'objet du premier xmiPrint. Réciproquement, le programme générique d'impression des maquettes se sert du nom du masque qui lui est fourni en paramètre pour reconstituer la liste des fichiers xml concernés et, s'il y en a plusieurs, proposer à l'utilisateur de choisir celui qu'il désire.

Le plus souvent, le programme à l'origine d'une série de maquettes charge un masque unique, les fichiers xml créés sont identifiés à partir du nom de ce masque et le programme générique d'impression des maquettes sait en reconstituer la liste.

Mais si le programme à l'origine des maquettes charge deux ou plusieurs masques, le programme générique d'impression des maquettes ne saura pas reconstituer la liste des fichiers xml concernés si le masque qui lui est fourni en paramètre n'est pas celui qui a fait l'objet du 1er xmiPrint.
