Opérations effectuées

La moulinette 
 - crée le fichier avec la nouvelle description des clés,
 - lit un enregistrement dans l’ancienne table,
 - transfère champ par champ les valeurs dans la nouvelle structure de la table,
 - écrit le nouvel enregistrement dans le nouveau fichier
 - etc.

Pour les champs traités :

  • Si le champ existe dans les deux tables, le nouveau champ reçoit la valeur de l’ancien champ (affectation diva).
    Si les caractéristiques des sous-champs d’un champ sont toutes identiques, l’affectation des sous-champs n’est pas générée puisqu’elle est inutile.

  • Si le champ n’existe pas dans l’ancienne table (c’est donc un nouveau champ ajouté à la table), le nouveau champ reçoit  :
    - la valeur initiale locale si cette dernière est précisée,
    - sinon, la valeur initiale globale si cette dernière est précisée,
    - sinon des espaces.
    Voir Valeur initiale des nouveaux champs .

 

Remarques

  • Tous les champs de la nouvelle table sont traités, exceptés ceux dont la propriété « Masqué dans SQL » est cochée. Les champs qui n’existent plus dans la nouvelle table sont ignorés.

  • Pour les fichiers dont la propriété « Sans reprise des données » est cochée dans le dictionnaire, la moulinette ne fait que créer le fichier avec les bonnes clés et la bonne version.

  • Les Unions ne sont pas traitées par les moulinettes, il est impossible de déterminer par programme les opérations à effectuer.
