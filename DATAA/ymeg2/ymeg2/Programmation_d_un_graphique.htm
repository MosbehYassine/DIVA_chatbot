Programmation d'un graphique

Les fonctions de programmation des graphiques sont regroupées dans le module yChart.dhop qui devra être référencé par les programmes appelant. Ceux-ci devront aussi inclure le fichier zChart.dhsp qui contient les définitions des constantes utilisées par de nombreuses fonctions des graphiques.

module "yChart.dhop"

include "zChart.dhsp"

La structure logique d'un objet graphe est constituée par un enregistrement IdChart du dictionnaire de donnée ddsys.dhsd.

La structure de cet enregistrement est la suivante :

IdChart

  • IdOptions

  • IdSeries

  • IdDataPoints

  • IdAxis

  • IdAnnotations

Les champs de l'enregistrement contiennent les identifiants des listes associées au graphe. Ces listes sont initialisées par la fonction XmeChartGetId.

Les options du graphe sont affectées grâce à la fonction XmeChartSetOption.

Les autres listes se manipulent avec les fonctions de liste usuelles.

Les éléments des différentes listes sont des chaînes hmp décrivant un point, une série, ou un axe. Ils sont à construire grâce aux fonctions du module yChart.dhop (voir la Liste récapitulative des fonctions du graphe).

 

Actions utilisateurs
Il est possible de traiter les clics de l'utilisateur sur un point ou sur une série d'un graphique.
Pour cela, il faut traiter le point d'arrêt associé au graphe et qui est levé de manière systématique quand un événement survient sur ce graphe.
 
La donnée Harmony.ChartClic permet de distinguer le lieu du clic et peut prendre les valeurs :
  • CHART_CLICK_SERIES : clic sur une série (soit clic sur la ligne ou dans la surface d'une série en ligne ou série surface, soit clic sur un point qui n'a pas d'identifiant de point).
  • CHART_CLICK_POINT : clic dans un point. Pour que cette option soit utilisable, il faut que le point source de l'événement dispose d'un identifiant de point explicitement défini.
Pour identifier le point et/ou la série à l'origine de l'événement, il faut scruter les données :
  • harmony.ChartSeriesId : identifiant de la série (celui-ci est toujours remonté).
  • harmony.Chart¨PointId : identifiant du point (celui-ci n'est remonté que si le clic est sur un point dont l'identifiant a été défini).

 

Remarques :

  • L'ordre dans lequel sont ajoutées les séries à la liste des séries est important car c'est l'ordre dans lequel ces séries seront rendues à l'écran/l'impression et une mauvaise gestion de cet ordre pourra conduire à des séries partiellement ou totalement masquées par les séries suivantes.

  • Rien n'interdit d'écrire les chaînes hmp décrivant les éléments du graphe "à la main", cependant il est fortement recommandé d'utiliser les fonctions du module yChart.dhop qui offre une garantie quand à la validité des chaînes hmp produites.
