XmeToolbarAddButton  Famille  Thème

Ajout d’un bouton à une barre d'outils

 

XmeToolbarAddButton (Id_Toolbar, Caractéristiques, Lieu, Bouton_de_référence, Prise_en_compte)

 

Paramètres :

Id_Toolbar

Identifiant de la barre d'outils rendu par la fonction XmeToolbarGetId.

Caractéristiques

Chaîne de caractères au format HMP (Harmony Markup Parameters), contenant les caractéristiques du bouton à créer (voir paragraphe Paramètres de création du nouveau bouton ci-après).

Lieu et
Bouton_de_référence

L’endroit dans la barre d'outils où sera inséré le nouveau bouton est défini par ces deux paramètres de la manière suivante :

  • Lieu = TOOLBAR_AFTER_ITEM :
    Insertion après le bouton identifié Bouton_de_référence.

  • Lieu = TOOLBAR_BEFORE_ITEM :
    Insertion avant le bouton identifié Bouton_de_référence.

  • Lieu = TOOLBAR_FIRST_ITEM :
    Insertion en tant que premier bouton.

  • Lieu = TOOLBAR_LAST_ITEM :
    Insertion en tant que dernier bouton.

Remarque :

Syntaxiquement, Bouton_de_référence est un paramètre facultatif ; cependant, ce paramètre doit contenir un identificateur de bouton valide avec les valeurs TOOLBAR_AFTER_ITEM et TOOLBAR_BEFORE_ITEM du paramètre Lieu.

 

Prise_en_compte

TRUE  : la barre d'outils doit être immédiatement réaffichée.
FALSE : la barre d'outils ne doit pas être immédiatement réaffichée.

FALSE permet d'optimiser les réaffichages de la barre d'outils lorsque vous effectuez plusieurs créations successives de bouton : ne mettez ce drapeau à TRUE qu'au tout dernier ajout.

Remarque : dans les versions d'Harmony précédant la version 7, cette optimisation n’affectait pas forcément les performances de manière visible. Mais elle peut s’avérer cruciale en client léger pour éviter un fort ralentissement de l’affichage.

Ce paramètre facultatif (TRUE par défaut) n’est significatif que si la barre d'outils est déjà affichée.

 

Description de la fonction :

La procédure XmeToolbarAddButton permet d’ajouter dynamiquement un nouveau bouton à la barre d'outils d’identifiant Id_Toolbar. Utilisez les paramètres Lieu et Bouton_de_référence pour préciser le lieu d’insertion du nouveau bouton dans la barre d'outils (Cf. texte ci-dessus).

 

Paramètres de création du nouveau bouton :

Les caractéristiques du nouveau bouton doivent être spécifiées dans le paramètre Caractéristiques. Il s’agit d’une chaîne de caractères au format HMP (Harmony Markup Parameters), pouvant contenir les paramètres et valeurs respectives suivants (sauf mention contraire, un paramètre est facultatif) :

<Bouton>

Nom d’un bouton dans la feuille de styles (32 caractères maximum - ignoré si séparateur).
Tous les paramètres de création du bouton sont récupérés dans la feuille de styles.
Voir aussi le paragraphe "Cas particulier du paramètre <Bouton>" dans la présente rubrique.

<Ident>

Identificateur.
En final, le bouton doit être obligatoirement identifié : si ce paramètre est absent, il faut que le paramètre <Bouton> soit présent et que la zone Identifiant du cadre Ressources soit renseignée dans la feuille de styles.

<Type>

Type et Nature :

  • NORMAL (valeur par défaut) : type Terminal et nature Normal.

  • CASE : type Terminal et nature Case à cocher.

  • RADIO : type Terminal et nature Bouton radio.

  • SEPARATEUR : type Séparateur.

<Libelle>

Texte (ignoré si séparateur).

<Police>

Nom de la police du texte dans la feuille de styles (32 caractères maximum - STD par défaut - ignoré si séparateur).

<Bitmap>

Nom d’image bitmap dans la feuille de styles (32 caractères maximum -
ignoré si séparateur).
Remarque 1 : une 1ère recherche est d'abord effectuée dans les boutons de la feuille de styles ; en cas de succès, le fichier image de ce bouton est utilisé ; en cas d’insuccès, une 2ème recherche est faite dans les images bitmaps de la feuille de styles pour assurer la compatibilité avec la version 5 d’Harmony.
Remarque 2 : aucune vérification n’est effectuée sur son existence.

<NomSelec>

Nom pour la sélection (32 caractères maximum - ignoré si séparateur).

<Bulle>

Bulle d'aide (ignoré si séparateur).

<Arret>
OU
<Chaine>

Numéro du point d'arrêt ou Chaîne à générer (ignoré si séparateur).
En final, un bouton terminal doit obligatoirement comporter un traitement (et un seul). Si ces deux paramètres sont absents, il faut que le paramètre <Bouton> soit présent et qu’un traitement valide (arrêt ou chaîne) lui soit associé dans la feuille de styles.
Le numéro de point d’arrêt doit être compris entre 1 et 65535. La chaîne doit respecter la même codification que celle utilisée à la saisie, dans les propriétés des boutons de Xwin.
Remarque : il n’est pas possible ici de générer un point de traitement.

<LicenceConsult>

0 ou 1.
Si cette option est positionnée à la valeur 1, le bouton est automatiquement grisé lorsque le programme s'exécute en mode "Licence consultation". Le cas échéant (voir la propriété "Chaine"), l'option invalide aussi automatiquement la touche affectée au bouton.

Rappelons que dans ce mode, toute modification dans une base de données Divalto est interdite. On pourra donc activer cette option pour tous les boutons commandant une fonction de création, modification ou suppression dans la base.

 

 

Cas particulier du paramètre <Bouton>

Le paramètre <Bouton> permet de récupérer - dans la feuille de styles - des valeurs qui font également l’objet d’un paramètre individuel. Il n’est pas interdit de préciser conjointement le paramètre <Bouton> et un ou plusieurs paramètres individuels. Dans ce cas, chaque paramètre individuel annule et remplace la valeur correspondante trouvée dans la feuille de styles.

 

Restriction d'utilisation du paramètre <Bouton> : La bulle et, le cas échéant, le texte du bouton sont recherchés dans la feuille de styles. Or cette dernière ne fait pas l'objet d'une traduction en langue étrangère. Si votre logiciel doit être traduit, n'utilisez pas ce paramètre ou alors faites-le suivre des paramètres <Bulle> et, le cas échéant, <Libelle> avec en paramètre des chaînes de caractères traduites (voir l'instruction Diva Translate).

 

Remarque :

Lorsqu'une même barre d'outils est affichée dans plusieurs fenêtres empilées, ses MISES A JOUR (grisages, invalidations, coches, ajouts ou suppressions de bouton, surcharge, ...) sont répercutées dans TOUTES les OCCURRENCES affichées.

 

Exemple :

1 Params 1000

...

 

;Ajout, en fin de barre d’outils, du bouton graphique Ouvrir

;générant le point d’arrêt numéro 11 :

Params = "<Ident>bouton_ouvrir<Arret>11" & \

         "<Bitmap>OUVRIR<Bulle>Ouverture d’un fichier"

XmeToolbarAddButton (Id_toolbar, Params, TOOLBAR_LAST_ITEM) 

 

;Ajout, après le bouton Ouvrir, du bouton texte Fermer

;générant le point d’arrêt numéro 12 :

Params = "<Ident>bouton_fermer<Libelle>Fermer<Police>Arial10" & \

         "<Arret>12<Bulle>Fermeture d’un fichier"

XmeToolbarAddButton (Id_toolbar, Params, TOOLBAR_AFTER_ITEM, \ 

                     "bouton_ouvrir") 

 

;Ajout, après le bouton Fermer, du bouton Quitter

;entièrement défini dans le bouton Quitter de la feuille de styles :

Params = "<Bouton>Quitter"

XmeToolbarAddButton (Id_toolbar, Params, TOOLBAR_AFTER_ITEM, \

                     "bouton_fermer")

 

;Ajout, avant le bouton Ouvrir, d’un séparateur :

Params = "<Ident>bouton_separateur<Type>Separateur"

XmeToolbarAddButton (Id_toolbar, Params, TOOLBAR_BEFORE_ITEM, \

                     "bouton_ouvrir")

 

;Ajout, en début de barre d’outils, du bouton texte+graphique

;Zoom articles nommé "zoom" pour la sélection et générant la touche

;de fonction F8 :

Params = "<Ident>bouton_zoom<Type>Normal<Libelle>Zoom articles" & \

         "<Police>Arial10<Bitmap>ZOOM<Chaine>#F8<NomSelec>zoom" & \ 

         "<Bulle>Appel du zoom des articles"

XmeToolbarAddButton (Id_toolbar, Params, TOOLBAR_FIRST_ITEM)
