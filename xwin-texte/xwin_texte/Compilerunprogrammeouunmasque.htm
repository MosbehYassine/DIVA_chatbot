Compiler un programme ou un masque

Tout source de masque ou de programme doit être compilé pour pouvoir être exécuté. Rappelons que Xwin propose deux modes de compilation :

  • Le mode "débogueur",
    qui vous permet de bénéficier des fonctions du débogueur lorsque vous mettrez au point votre programme.
    L'option "Couverture du code" vous permet de bénéficier de la fonction supplémentaire de couverture du code (uniquement dans le cadre d'un projet de Xwin).

  • Le mode "normal",
    qui vous permet de générer le code objet utilisé en exploitation.

 

Pour compiler les sources modifiés du sous-projet courant :

  • Sélectionnez le choix Construire le sous-projet du menu Projet (raccourci clavier : F10).

  • Ou cliquez sur le bouton de la barre d'outils.

Pour compiler un source isolé du sous-projet courant :

  • Activez la fenêtre contenant ce source.

  • Sélectionnez le choix Compiler du menu Projet (raccourci clavier : Maj+F10).

  • Ou cliquez sur le bouton de la barre d'outils.

Pour compiler les sources modifiés du projet courant :

  • Sélectionnez le choix Construire le Projet du menu Projet.

Pour recompiler tous les sources du sous-projet courant :

  • Sélectionnez le choix Reconstruire Tout le Sous-projet du menu Projet.

Pour recompiler tous les sources du projet courant :

  • Sélectionnez le choix Reconstruire Tout le Projet du menu Projet.

 

Pour compiler un programme HORS PROJET :

  • Si vous N'avez PAS précisé le nom du source à compiler dans les options de compilation, activez la fenêtre contenant le source du programme en question (si vous avez précisé le nom du source dans les options de compilation, cette activation n'est pas nécessaire).

  • Sélectionnez le choix Compiler du menu Projet (raccourci clavier : Maj+F10).

  • Ou cliquez sur le bouton de la barre d'outils.

Pour compiler un masque HORS PROJET :

  • Activez la fenêtre contenant le masque.

  • Sélectionnez le choix Compiler du menu Projet (raccourci clavier : Maj+F10).

  • Ou cliquez sur le bouton de la barre d'outils.

Remarque : la compilation d'un dictionnaire n'est pas disponible hors projet.

 

 

Remarques :

  • Lorsque la fenêtre « compte rendu » est en mode « Masquage automatique », le lancement d’une compilation ouvre la fenêtre pour vous permettre de consulter les éventuelles erreurs et lui transfert le focus pour qu’elle ne se referme pas immédiatement. Pour redonner rapidement le focus à la fenêtre d’édition Mdi, tapez la touche Echap.

  • Au lancement d'une compilation, Xwin sauvegarde automatiquement TOUS les fichiers source édités modifiés.

  • Pour pouvoir utiliser le débogueur, vos programmes (et vos masques et dictionnaires, pour les procédures de traitement) doivent être compilés en mode "débogueur". La mise en route de la fonction de couverture du code nécessite l'option supplémentaire "Couverture du code".

  • La compilation en mode "débogueur" (ainsi qu'en mode "Couverture du code") génère des informations spécifiques. Il en résulte une augmentation de la taille du code généré et, accessoirement, un possible ralentissement de l'exécution. En conséquence, lorsque votre programme est validé, n'oubliez pas de le recompiler en mode "normal" et utilisez la version correspondante du code objet en exploitation.

  • Les compilations s'effectuent en tâche "de fond" : durant une compilation, vous conservez la main pour éditer d'autres sources, pour naviguer dans votre application, … L'exécution du programme est par contre interdite.
    Exception : hors projet, une compilation de masque est faite par l'éditeur lui-même : vous perdez la main durant la compilation et vous devez en attendre la fin pour la récupérer.

  • Hors projet : si vous avez paramétré un dossier de stockage des fichiers objet, un objet qui n'existe pas encore dans ce dossier est automatiquement créé à la compilation. Si le nom du source ne comporte pas d'extension, le nom de l'objet est déduit du nom du source en lui ôtant son premier caractère (exemple : SPROG => PROG) ; sinon, l'extension .dhsp est remplacée par .dhop (exemple : PROG.dhsp => PROG.dhop).
