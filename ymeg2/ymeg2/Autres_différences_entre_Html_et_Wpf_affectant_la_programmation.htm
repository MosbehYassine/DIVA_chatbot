Autres différences entre Html et Wpf affectant la programmation

 

Cette dernière rubrique mentionne quelques différences de programmation entre les modes Html et Wpf :

  • XmeSetColorTheme doit être appelé avant tout affichage.
     

  • Xwpf retaille automatiquement la fenêtre en cas d'ajout d'un menu programmé après le premier affichage. Xhtml5 ne le fait pas, ce qui entraîne l’apparition d'ascenseurs. Il est donc conseillé de spécifier le menu qui doit être associé à une page Xwin avant son 1er affichage.
     

  • System.Zquit.
    Cet indicateur permet, sous Xwpf, de refermer par programme plusieurs sous-fenêtres et la fenêtre principale en cascade (voir la rubrique "Fermeture d'une fenêtre par Alt+F4"). Il n’est pas fonctionnel en Html pour les raisons suivantes :

    • A partir du deuxième niveau de sous-fenêtre, il n'est pas possible de cliquer sur la croix de fermeture d'une sous-fenêtre qui n’est pas celle couramment active (la croix est grisée et désactivée).

    • Alt+F4 referme purement et simplement le navigateur (voir Traitements effectués en cas de fermeture du navigateur).
       

  • Copie et exécution de fichiers Windows

    • Fonction LcWinDownload (FichierDepart, &FichierArrivee).

      • En client léger Wpf, cette fonction copie le fichier de départ (situé sur le serveur) vers le fichier de destination (situé sur le poste client).

      • Le client léger Html ne tient pas compte du paramètre FichierArrivee ; le fichier de départ est directement téléchargé vers le poste client. Mais le navigateur client n’acceptera pas le transfert si l’extension du fichier lui est inconnue.
        Cela peut poser problème si l’extension précisée dans le nom du fichier de départ n’est  pas celle correspondant effectivement au contenu du fichier. Par exemple, lorsque le fichier de départ est un fichier temporaire d’extension .tmp car cette dernière n’est pas reconnue par le navigateur.

        La solution consiste ici à produire un fichier de départ directement avec la bonne extension        .

        D’autre part, si le navigateur demande confirmation du téléchargement du fichier, le programme Diva ne doit pas se terminer immédiatement derrière l’instruction car la fenêtre du navigateur se fermera avant que l’utilisateur ait pu répondre à la demande. Le cas échéant, une solution consiste à faire suivre l’instruction d’une MessageBox.

  • La fonction LCWinUpload (copie d'un fichier du client vers le serveur) est utilisable dans deux cas précis :

    • Après un drag & drop de fichiers dans la fenêtre du navigateur.

    • Après appel à la fonction WinGetOpenFileName.

Les fichiers déposés ou sélectionnés sont placés dans un flux interne au navigateur, ce qui permet ensuite de les récupérer en appelant la fonction LCWinUpload.
Attention : Ce flux n’est valide que 15 minutes.

Un appel « direct » à cette fonction en spécifiant un fichier quelconque du poste client n’est pas possible.

  • La fonction LCWinShellExecute (exécution d'un programme associé à un fichier) peut être utilisée en particulier pour afficher une url Web ou un fichier .dhvw :

    • Une url Web est transmise au navigateur du client, qui affiche cette url dans une fenêtre à part.

    • Un fichier .dhvw est considéré comme situé sur le serveur, il est converti en PDF et le fichier PDF résultant est téléchargé sur le navigateur du client. Le poste client pourra lire ce fichier avec Acrobat Reader.

    • Avec d’autres types de fichier, la fonction est difficilement utilisable car elle nécessite de connaître le chemin du fichier sur le poste client.

  • La fonction WinGetOpenFileName ouvre la boîte de dialogue de sélection des fichiers de Windows (voir fonction LCWinUpload ci-dessus).
     

  • Les autres fonctions "Windows" soit ne sont pas fonctionnelles (LcWinGetFilesAttributes, LcWinSetFilesattributes, WinGetSaveFileName, WinShBrowseForFolder, …), soit attaquent le serveur (WinDirGetFile, FindExecutable, GetTempPath, WinCreateDirectory, LCWinShGetSpecialFolderLocation, …).
     

  • Fonction ServiceModeTransport.
    Cette fonction renvoie la (nouvelle) valeur 4 en mode client léger Web.
    Un programme Diva peut tester s’il est exécuté depuis un client html ainsi :
         if ServiceMode = 7 and ServiceModeTransport = 4 …
     

  • Fonction Winprint.
    Cette fonction ne traite que les fichiers de type .pdf ou .dhvw (automatiquement convertis en PDF).
     

  • Le changement dynamique d'épaisseur d’un trait oblique n'est pas correctement traité.
