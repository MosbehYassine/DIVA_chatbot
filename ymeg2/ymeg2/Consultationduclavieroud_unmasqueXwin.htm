Consultations clavier sous Harmony

Voyons pour terminer le cas des fonctions de consultation clavier :

  • Elles positionnent Harmony.Key et les indicateurs ShiftKey et ControlKey.

  • Elles fournissent aussi comme résultat le code ANSI de la touche tapée.
    Mais certaines touches n’ont pas de code ANSI associé (touches de fonction, par exemple).
    On aura donc intérêt à tester systématiquement la valeur de Harmony.Key pour identifier la touche tapée. A cet effet, les touches "normales" (lettres, chiffres, etc.) positionnent Harmony.Key à la valeur K_ANSIKEY_OFFSET+nnn, où nnn est le code ANSI de la touche.

 

Fonctions XmeConsult et XmeListConsult de Ywpf

  • Les touches Ctrl+Tab (respectivement Maj+Ctrl+Tab) font automatiquement passer à la page suivante (respectivement précédente) en cas de masque multi-écran (pages chaînées). Elles rendent la main dans le cas contraire.

  • Toutes les autres touches significatives rendent le contrôle au programme appelant.
    En particulier, Shift+F1 ne fait l'objet d'aucun traitement automatique (contrairement aux fonctions XmeInput et XmeListInput) : l’affichage éventuel d’une fenêtre d’aide est donc ici à la charge du programme appelant.

 

GetChar et GetbChar

Attention : ces fonctions positionnent Harmony.Key uniquement si vous donnez à leur paramètre d'entrée (facultatif) la valeur TRUE (qui n'est pas la valeur par défaut pour des raisons de compatibilité avec les versions antérieures d'Harmony).
