OrderBy   Famille  Thème

 

La balise OrderBy permet de définir des critères de tri. Elle ne comporte pas d’attributs.

 

<OrderBy>

case OrderByName_1      [Commentaire] [Dependencies="T1;Alias2"] [ColumnNames="nom1;nom2"] [NoCheckOrderBy]

Liste_des_colonnes

case OrderByName_2      [Commentaire] [Dependencies="T1;Alias2"] [ColumnNames="nom1;nom2"]

Liste_des_colonnes

 

Chaque critère est identifié par un nom unique qui lui permet d'être sélectionné par le programme Diva.

  • Commentaire : Ce libellé facultatif apparaît, dans le ZoomSQL, dans le multichoix permettant de sélectionner des critères de tri prédéfinis.
     

  • Dependencies : Cet attribut permet d'indiquer la ou les jointures nécessaires à l'exécution du tri. Son fonctionnement est le même que l'attribut Dependencies de la jointure.
     

  • ColumnNames : Cet attribut permet d'indiquer les noms des champs pour faire le lien avec les champs du Select, séparés par des points-virgules.

  • NoCheckOrderBy : Voir le paragraphe ci-dessous sur les contraintes de l'ordre de tri.

Liste des colonnes

A partir de la ligne suivant le case, on trouve la liste des colonnes, du critère majeur vers le critère mineur. L’option ASC (par défaut) indique que l’on souhaite un tri croissant sur la colonne, l’option DESC un tri décroissant.

{ table | alias }.columnName { ASC | DESC }

 

Contraintes de l'ordre de tri

Le compilateur vérifie que

  • si un critère est en mode DESC, tous les critères doivent être en mode DESC. Si cela n'est pas le cas, le serveur SQL risque de répondre avec des temps de réponse dégradés.

  • si un critère est en mode DESC, le champ _ID doit impérativement être présent dans la liste des critères.

Pour que la vérification soit effectuée il faut positionner l'option GCheckOrderBy dans les options de compilation

Cette vérification peut être ignorée pour un OrderBy en ajoutant le mot clé NoCheckOrderBy

 

 

Exemple

<OrderBy>

Case Par_Telephone

VRP.Dos,

VRP.Ce1,

VRP.Tel

 

En diva :

Rec.OrderBy.Par_Telephone()

 

Remarques

  • Dans une surcharge, il est possible de surcharger un tri. Dans ce cas, les nouveaux critères sont ajoutés aux anciens.

  • Pour des raisons de performances, il est conseillé de faire correspondre les critères de tri à un index de la base.
