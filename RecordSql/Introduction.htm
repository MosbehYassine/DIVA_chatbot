Introduction

 

RecordSQL est l'objet qui permet d'accéder à la base de données. Il comporte deux aspects :

  • C’est une structure de données utilisable dans les programmes Diva et les masques, de la même manière que les Record.

  • Il définit des méthodes d’accès à la base de données.
    Par exemple, Facture.Select() où Facture représente une instance du RecordSQL de la facture.

Les RecordSQL sont décrits dans des dictionnaires de RecordSQL. Un dictionnaire est un fichier source d’extension .dhsq, compilé dans un fichier objet d’extension .dhoq.


 

Opérations réalisées par un RecordSQL

Le RecordSQL permet de lire les données (Select), de les modifier (Update), de créer (Insert) ou de supprimer (Delete) des lignes.

 

Format du source d'un dictionnaire de RecordSQL

Le source du dictionnaire est écrit dans un langage spécifique à balises. Il se saisit dans l'éditeur de textes de Xwin.

Il regroupe un certain nombre de RecordSQL, chacun d'eux ayant la structure générale d’un ordre Select du langage SQL. On y retrouve les balises <Select>, <From>, <Join>, <Where>, <GroupBy>, <Having>, <Orderby>.

La balise <Select> contient la liste des champs (ou des expressions) de la clause Select du langage SQL.
Les balises <From> et <Join> font référence à la description des tables dans les dictionnaires de données d’Harmony.

 

Utilité des RecordSQL

L'objet RecordSQL est une couche d'abstraction qui assure l’indépendance entre d'une part les programmes et les masques et d'autre part le schéma des tables dans la base de données. Ainsi, par exemple, si le champ Facture.Adresse du RecordSQL Facture représente l’adresse de livraison, le développeur qui l'utilise ignore de quelle table ce champ est issu et il peut donc restructurer les tables sans remettre en cause les développements existants.

De plus, un RecordSQL est plus riche qu’une simple requête du langage SQL. Il peut contenir plusieurs clauses Where, Having ou Order by. La requête est à géométrie variable, autorisant le développeur à combiner à loisir ces différentes clauses.

 

Compatibilité

Pour des raisons de compatibilité avec les anciens développements, une table d’un RecordSQL peut être liée (BIND) avec une instance publique du Record de la table (pour plus de détails, consultez la rubrique Bind).

 

Surcharge des RecordSQL

Les RecordSql peuvent être surchargés, à un ou plusieurs niveaux. Le mécanisme de la surcharge permet d'ajouter des colonnes à la requête, des tables jointes, des filtres, etc.
