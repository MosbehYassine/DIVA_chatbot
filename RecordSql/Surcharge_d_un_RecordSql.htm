Surcharge d'un RecordSql

 

Déclaration

Pour surcharger un RecordSql existant, il suffit de le déclarer dans la surcharge avec son nom dans le dictionnaire surchargé.

 

Champs et Records publics

Dans le dictionnaire de surcharge, on peut faire référence aux champs de la section <Select>, ainsi qu’aux champs des Records publics du ou des dictionnaires surchargés.

 

Préfixage

On prendra soin dans les surcharges de respecter les conventions de préfixage afin d’éviter des conflits avec des modifications apportées par l’éditeur dans de futures versions.

 

Quels sont les éléments surchargeables ?

Dans un RecordSQL, tout n’est pas surchargeable. Voir ci-dessous la liste exhaustive des possibilités de surcharge. Tout ce qui n’est pas expressément autorisé est interdit.

 

Déclaration de Record Public

Il est possible d’ajouter des déclarations de  Record Public.

Exemple :

Public Record XXFDD.dhsd XX_MonREcord

 

BIND

Il est possible (avec modération et uniquement si cela est strictement nécessaire, l’abus de Bind pouvant nuire gravement à l’équilibre du programme utilisant le RecordSQL) de lier des tables ajoutées dans les sections <JOIN>.

Attention, il est strictement interdit de lier des tables existantes qui n’auraient pas été liées par l’éditeur.

 

<SELECT>

Il est possible d’ajouter de nouveaux champs provenant des tables existantes ou de nouvelles tables jointes.

Pour ajouter tous les nouveau champs on peut écrire table.*

 

 

<JOIN>

Il est possible d’ajouter des tables jointes. Théoriquement, toutes les formes de jointures peuvent être ajoutées, mais on veillera à n’utiliser que les formes qui ne perturberont pas le déroulement des programmes existants utilisant le RecordSQL.

 

A partir de la version 7.2a, il est également possible de surcharger des jointures existantes pour ajouter des noms, des dépendances et des "ColumnNames". Il n'est pas possible de modifier la condition de jointure.

Pour pouvoir identifier une jointure, il faut reprendre la table et son alias du dictionnaire de base.

 

Exemple :

Dans le dictionnaire de base :

<LeftJoin>

Art as ArticleRemplacement

ON ArticleRemplacement.dos = .....

 

Dans le dictionnaire de surcharge :

<LeftJoin Dependencies="STB">

Art as ArticleRemplacement

 

 

<WHERE> ou <HAVING>

Il est possible :

  • d’ajouter de nouveaux critères de sélection.

  • de modifier intégralement un critère de sélection déclaré public dans le dictionnaire surchargé.
    Le mot clé Standard permet de faire référence à la condition du record surchargé

  • D’ajouter des critères de sélection à une condition existante. Les critères ajoutés sont liés aux critères existants par un ET Logique (AND). Les critères déclarés Private dans la base ne peuvent pas être modifiés. Voir Where.

  • De modifier le libellé du critère de sélection.

  • D'ajouter des dépendances (à partir de la version 7.2a).

Exemple de surcharge avec appel de la fonction de base.

<where>

     Case ParRef(char ref)

          Standard or lower(art.ref) = lower(ref)

 

 

<ORDERBY>

Il est possible :

  • D’ajouter de nouveaux critères de tri.

  • D’ajouter des critères de tri mineurs à un tri existant.

  • De modifier le libellé du critère de tri.

  • D'ajouter des dépendances (à partir de la version 7.2a).
