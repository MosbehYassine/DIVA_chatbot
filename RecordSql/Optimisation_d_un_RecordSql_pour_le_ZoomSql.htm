Optimisation d'un RecordSql pour le ZoomSql

 

Pour accélérer l'affichage du ZoomSql, il faut que la requête soit la plus simple possible. Un des moyens est de ne pas exécuter les jointures qui ne servent pas à l'affichage du mode liste du Zoom, tout en les laissant pour l'affichage du mode fiche.

Pour permettre cette désactivation automatique, il faut mettre en place un certain nombre de choses.

 

Tout d'abord, il faut positionner le paramètre "ZoomOptimize" du RecordSql à yes :

 

<RecordSql ZoomOptimize=yes>

 

Ensuite, la présence de cet attribut entraîne la nécessité de donner un "Name" aux expressions. Un champ ne peut avoir qu'un seul Name, mais plusieurs champ peuvent posséder la même valeur de Name.

Ce Name servira à retrouver les jointures qui servent au calcul de ce champ.

 

Au niveau des jointures, toutes celles utilisées par le ZoomSql doivent porter le nom Name="ZOOM".

Les jointures qui sont utilisées par une expression dans le Select doivent faire le lien avec ces champs via l'attribut "ColumnNames". Cet attribut est une liste de noms séparés par un point-virgule. Ces noms sont les valeurs de l'attribut Name des champs du Select.

 

A l'entrée du ZoomSql, plusieurs traitements sont effectués :

  • il désactive toutes les jointures qui ne portent pas le nom "ZOOM" ;

  • il supprime de la requête tous les champs qui ne sont pas affichés dans le tableau à l'exception des champs renseignés dans le chapitre "MandatoryColumns" ;

  • il supprime toutes les jointures qui ne sont pas utiles pour les champs à sélectionner.

 

Pour l'affichage du mode fiche, seul le premier point est effectué : en effet, en mode fiche, il faut que tous les champs soient renseignés.

 

Dans la procédure ZoomDebut, il est possible d'activer/désactiver des jointures/colonnes via les fonctions RecordSql.Column.Activate, RecordSql.Column.Deactivate, RecordSql.Join.Activate et RecordSql.Join.Deactivate. Ces modifications seront effectives dans les deux modes (liste et fiche).

 

Une nouvelle procédure est également appelée : ZoomApresReadListe qui remplace ZoomApresRead dans le cas du remplissage du tableau. Si elle n'existe pas, c'est ZoomApresRead qui est appelée.

 

 

Exemple :

 

<RecordSql Name="Articles" ZoomOptimize=yes>

<Select>

Art.*

ClientImportant.Nom

COALESCE(Chemin1.chemin, Chemin2.Chemin) as CheminConfigurateur (>a5dd.dhsd Chemin) Name="chemin"

<MandatoryColumns>

Art.HsDt

<From>

gtfdd.dhsd Art

<LeftJoin Name="Zoom">

gtfdd.dhsd STB as STB

on ...

<LeftJoin Name="Zoom" Dependencies="STB">

gtfdd.dhsd CLI as ClientImportant

on ClientImportant.Tiers = STB.Tiers ....

<LeftJoin Name="Zoom" ColumnNames="chemin">

gtfdd.dhsd MChemin as Chemin1

...

<LeftJoin Name="Zoom" ColumnNames="chemin">

gtfdd.dhsd MChemin as Chemin2

...

<OrderBy>

case MonTri "Mon tri" Dependencies="ClientImportant"

Art.Ref

ClientImportant.Nom

 

Si le tableau du mode liste ne contient que des champs de la table ART, il n'y aura aucune jointure d'exécutée.

Si le champ "ClientImportant.Nom" est affiché dans le tableau, alors la jointure vers CLI sera activée ainsi que toutes ses dépendances, donc ici, STB.

Si le champ "CheminConfigurateur" est affiché dans le tableau, alors toutes les jointures qui possèdent un ColumnNames "chemin" seront activées. Ici, c'est les deux jointures Chemin1 et Chemin2.

Si seuls des champs de Art sont affichés et qu'on applique le tri "MonTri", alors la jointure vers CLI sera activée ainsi que sa dépendance vers STB.

 

Dans tous les cas, le champ Art.HsDt sera toujours ramené.
