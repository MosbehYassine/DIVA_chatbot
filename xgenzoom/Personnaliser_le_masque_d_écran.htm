Personnaliser le masque d'écran

Cette rubrique détaille les différentes possibilités qui vous sont proposées pour influer sur le rendu du masque, en particulier en cas de génération d'un zoom exécuté dans l'environnement de l'ERP Divalto.


 

Répartition des champs de la table sur les différentes pages du mode Fiche

  • Répartition "standard".
    Les champs, précédés de leur libellé respectif, sont rangés en colonne sur la page 3 du masque. Si la place en page 3 est insuffisante pour contenir tous les champs, la répartition se poursuit sur les pages suivantes.

     

  • Paramétrage de la répartition au niveau du dictionnaire de données.
    Lorsque les champs de la table doivent être répartis sur plusieurs pages, on positionne généralement des onglets pour simplifier la navigation entre les pages. Vous pouvez agir sur la répartition des champs dans les différentes onglets avec les paramètres suivants du dictionnaire des données :

    • Dans la propriété des tables Titre des onglets, vous pouvez saisir une liste de "titres d'onglet" (séparés par des virgules). Dans ce cas, le masque généré inclura les onglets indiqués, en pages 3, 4, 5, etc. Les textes saisis seront affichés comme titre des onglets correspondants.

    • Dans la propriété des champs Regroupement dans zoom, vous pouvez préciser à quel onglet chaque champ devra appartenir.

Attention : Si la table spécifie deux (ou plusieurs) titres d'onglet, seuls les champs dont la propriété de regroupement dans zoom est renseigné seront placés dans l'onglet correspondant (à partir du second). Les champs ayant cette propriété à espace seront d'abord placés dans le premier onglet (en page 3) ; si la place en page 3 est insuffisante, les champs restants seront placés dans des onglets générés après les onglets spécifiés dans la table.
 

  • Personnalisation de la répartition suivant la page 3 du masque modèle.
    Placez un onglet sur la page 3 du masque modèle (titre quelconque). La répartition des champs peut être réalisée de trois manières :

    • La page 3 du masque modèle contient un objet cadre unique (Cf. ModeleZoom.dhse).
      Les champs sont alors rangés en colonne.
       

    • La page 3 du masque modèle contient deux objets cadres (un à gauche, l'autre à droite) (Cf. ModeleZoom1.dhse).
      Les champs sont alors placés d'abord dans la première colonne puis, lorsque celle-ci est pleine, dans la seconde.
      Exemple :

      |  champ_1   |   champ_14  |
      |  champ_2   |   champ_15  |
      .                    .
      .                    .
      |  champ_13  |  champ_26  |
       

    • Comme précédemment, la page 3 du masque modèle contient deux objets cadres et, de plus, le libellé de cette page (F3, champ "Libellé") contient le texte "Colonne". (Cf. ModeleZoom2.dhse).
      Les champs sont alors alternés entre les deux colonnes (en Z).
      Exemple :

      |  champ_1   |   champ_2   |
      |  champ_3   |   champ_4   |
      .                    .
      .                    .
      |  champ_25  |  champ_26  |

 

Remarques :

  • Le ou les cadres servent aussi à délimiter la zone de rangement des champs.
    Ils ne sont pas reportés dans le zoom généré.

  • En cas de débordement, le modèle d'onglet de la page 3 est utilisé pour toutes les pages nécessaires au mode Fiche.


     

  • Ajout d'onglets modèles dans le masque modèle.
    Vous pouvez dessiner un ou plusieurs onglets modèles à partir de la page 4 du masque modèle. Un tel onglet fait l'objet du traitement particulier suivant :

    • Son texte fait référence à la liste des "titres d'onglet" de la table (propriété des tables Titre des onglets).
      Si ce texte est dans la liste, l’onglet modèle sera copié dans la page correspondante du masque généré.

    • Les champs de la table dont le nom correspond à une donnée présente dans l'onglet modèle seront placés dans cet onglet (voir le paragraphe "Dessin d'un onglet modèle" ci-dessous).

    • Exemple pratique - cas de l'onglet "Identifiants" :
      Les zooms de Divalto incluent souvent l'onglet "Identifiants" (Cf. page 4 du masque ModeleZoom.dhse). Cet onglet affiche des données "communes" à de nombreuses tables (codes enregistrements, notes, fichiers joints, dates de création, de dernière modification, de dernière opération, ...). Pour inclure cet onglet dans le zoom généré, ajoutez le titre "Identifiants" dans la propriété "Titre des onglets" de la table.

      Remarque       : Si la table ne spécifie aucun titre d'onglet, si l'onglet "Identifiants" est présent dans le masque modèle et si la table contient au moins un champ concerné, cet onglet sera automatiquement ajouté, en dernier (mais attention, cette remarque ne s'applique qu'à l'onglet modèle de nom imposé "Identifiants").

      Remarque       : Si la table spécifie des titres d'onglet qui ne sont pas des onglets modèles, la répartition dans ces onglets sera basée sur le dessin de la page 3 du masque modèle (comme indiqué au paragraphe "Personnalisation de la répartition suivant la page 3 du masque modèle").
       

Dessin d'un onglet modèle :
Un onglet modèle inclut des cadres, des libellés, des données (champs, multi-choix, ...). Tous ces objets ne sont toutefois pas systématiquement conservés dans le masque généré. En effet, on souhaite que les modèles d'onglet soient les plus généraux possibles et qu'ils s'adaptent immédiatement à des tables qui n'en sont que des sous-ensembles.

Prenons l'exemple de l'onglet modèle "Identifiants" : celui-ci contient tous les codes enregistrements possibles (Ce1, Ce2, ..., Ce9, Cea) alors que les tables à générer ne contiendront le plus souvent qu'une partie de ces codes. Ainsi, si une table ne contient par exemple que les codes Ce1 et Ce2, on souhaite évidemment que le zoom généré présente uniquement ces deux codes ; si la table ne contient aucun code, on souhaite non seulement n'afficher aucun des champs codes mais également ne pas afficher le cadre "Codes enregistrements".

Voici le mécanisme adopté par le générateur pour supprimer du zoom généré les objets non concernés pour une table donnée :

    • Cas des données (Champs, Multi-choix, etc.).
      Dans le modèle, les données peuvent appartenir à une table quelconque. Seul le nom importe : Si la table à générer contient une donnée de même nom, la donnée correspondante du modèle sera conservée dans le masque généré (bien entendu, après substitution du nom du modèle par le "vrai" nom) ; dans le cas contraire, cette donnée du modèle sera ignorée.
       

    • Cas des autres types d'objet (Texte, Cadre, ...).
      Pour un autre type d'objet, on établit un "lien" entre cet objet et une donnée, en plaçant le nom de la donnée dans sa propriété "Noms de l'objet" (remarque : on pourra attribuer plusieurs noms d'objet à un même objet afin de le lier à plusieurs données) :

      • Un objet sans nom d'objet (zone "Noms de l'objet" à blanc) sera conservé.

      • Un objet dont un des noms d'objet correspond à une donnée de la table sera aussi conservé.

      • Un objet dont aucun des noms d'objet ne correspond à une donnée de la table sera éliminé.
         

  • Résumé de l'algorithme utilisé pour la répartition des champs en mode Fiche.

    • On considère tous les champs non masqués de la table et on leur attribue un numéro d’onglet (en utilisant le cas échéant leur propriété Regroupement dans zoom).

    • Pour chaque onglet, on vérifie s'il est référencé dans la liste des titres d'onglet de la table et si le titre correspond à un onglet modèle :

      • Si l'onglet modèle n'existe pas, on génère l’onglet et on y place les champs de la table, en appliquant les règles de positionnement déduites du dessin de la page 3 du masque modèle.

      • Si l'onglet modèle existe, on balaye tous les objets de l’onglet modèle :

        • On recopie une donnée si elle appartient à la table (et n'y est pas masquée).

        • On recopie un autre type d'objet si sa propriété "Noms de l’objet" est à espace ou si l'un des noms correspond à un nom de champ de la table (non masqué).

 

 

Ordre des modes liste

L'ordre des modes listes dépend de la propriété des index "No du mode Liste" dans le dictionnaire des données. Un index portant le numéro 0 ne génère pas de mode liste, SAUF si TOUS les index ont leur No du mode Liste à 0, auquel cas toutes les clés génèreront un mode Liste, en suivant l’ordre des index dans le dictionnaire.

 

 

Pour qu'un champ n'apparaisse pas dans le masque

Dans les paramètres des champs dans le dictionnaire, mettez la propriété Masqué dans le masque zoom de la famille Avancé à la valeur Oui.

 

 

Présentation des objets

La présentation des objets du masque dépend :

  • Globalement, de la feuille de styles et du modèle de présentation (paramètres du projet).
    Dans les paramètres saisis au lancement de la génération, la case à cocher "Taille des boîtes des champs par palier" permet d'influer sur la taille des boîtes de saisie des champs.

  • Pour chaque champ, des paramètres de la famille Présentation (paramètres des champs dans le dictionnaire).
    Toujours au niveau de chaque champ, le titre de l'en-tête des colonnes des modes Liste peut être paramétré dans la propriété  "Nom de colonne dans zoom" et la propriété "No de colonne dans zoom" peut être utilisé pour placer le champ dans une colonne affichée de manière permanente.

 

Tables liées

Pour qu'une table liée soit prise en compte par le générateur :

  • Créez l'index et le lien dans le dictionnaire de données.

  • Dans les propriétés de la table liée dans le dictionnaire, renseignez la propriété "Libellé" de la famille "Générateur de zoom".
    Si le lien doit apparaître en mode Liste, positionnez aussi la propriété "Aff. libellé mode Liste" à Oui.

  • Lorsque le tableau des tables liées est affiché (à l'exécution de la génération), n'oubliez pas de cocher la ligne affichant la table à générer avant de valider.
