Surcharge des fonctions/procédures

La surcharge permet de réécrire une fonction d'un module. C'est la méthode pour verticaliser un progiciel.

La surcharge permet de rediriger les appels de fonctions/procédures externes d'un module, vers les fonctions/procédures d'un autre module.

Le prototype de la fonction dans le module de surcharge doit être exactement identique à celui de la fonction dans le module surchargé.
 

Exemple :

Programme P

Module M1

Module de surcharge M1S

Module "M1"
st = F1(i)

Public function int F1(i)
1 i X
Beginf
……….
Endf

Public function int F1(i)
1 i X
Beginf
………
Endf

Le programme P appelle les fonctions du module M1. Si le module M1 est surchargé par le module M1S, ce sont les fonctions de M1S qui sont appelées en remplacement des fonctions de M1. La surcharge est donc transparente pour le programme P qui ne connaît pas l'existence du module de surcharge.

 

Déclaration de la surcharge par OverWrite et OverWrittenBy.

Pour qu'un module puisse être surchargé, il doit contenir l'instruction OverWrittenBy "module-de-surcharge". OverWrittenBy indique que le module courant peut être surchargé et indique le nom du module de surcharge.

Un module de surcharge doit contenir l'instruction OverWrite "module-à-surcharger".

Appel du module de surcharge

L'appel du module de surcharge est transparent. Dès que le programme appelle une fonction du module surchargé, si cette fonction existe dans le module de surcharge, c'est cette dernière qui est appelée. 

 

Appel de la fonction du module surchargé.

Le module de surcharge a la possibilité d'appeler une fonction du module qu'il surcharge. Pour ce faire, le nom de la fonction doit être préfixé par "Standard.".
Dans l'exemple ci-dessus, l'appel de la fonction F1 du module M1 s'écrit : Standard.F1(i).
 

Remarques :

  •  A l'exécution, la présence du module de surcharge n'est pas obligatoire. Cela permet de prévoir à l'avance quels sont les modules qui pourront être surchargés et de développer les modules de surcharge sans avoir à modifier les modules de base. 

  • Un module de surcharge peut également contenir des fonctions publiques. Le module de surcharge peut être utilisé comme un module ordinaire.

  • En surcharge multiple, on peut préciser le nom de l'add-on qui contient la fonction. Voir Arbitrage de l'ordre d'appel des fonctions
