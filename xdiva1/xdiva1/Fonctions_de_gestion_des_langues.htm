Fonctions de gestion des langues

 

Les fonctions de gestion des langues permettent de :

  • Connaître le code langue courant.

  • Sélectionner un code langue.

  • Récupérer la liste des langues disponibles.

  • Demander la traduction d'un libellé.

  • Demander la traduction d'une donnée multilingue.

  • Connaître les paramètres associés à une langue : Code page, séparateur des milliers, séparateur décimal, séparateur de date.

Les fonctionnalités multilingues sont décrites en détail dans le livre  "Traduction des applications" du "Manuel de référence d'Harmony".

 

Remarques concernant les codes page

En standard, Harmony utilise le jeu de caractère ANSI latin occidental. Les caractères ANSI sont codés sur 8 bits (256 caractères différents). Le nombre de combinaisons est insuffisant pour coder l’ensemble de tous les caractères des alphabets utilisant le jeu ANSI. C’est pourquoi, il a été ajouté une notion complémentaire qui est le « code page » des caractères.

Un même code dans deux codes page différents ne sera pas représenté par le même symbole.

Exemple : le code 0xe6 correspond au symbole :

ć          dans le code page Europe centrale

æ         dans le code page Europe occidentale

Il existe une dizaine de codes page différents (Occidental, Hébreu, Arabe, Grec, Turc, Baltique, Europe centrale, Cyrillique, Vietnamien).

La plupart des pays d’Europe utilise le code page « Occidental ». C’est le code standard de Divalto.

Le polonais utilise le « code page » Europe centrale pour les caractères « spéciaux » de l’alphabet polonais. Si l’on souhaite afficher ces caractères, il faut utiliser une police de caractères avec le code page « Europe centrale ».

Remarque

Les 128 premiers caractères du jeu ANSI sont communs à l’ensemble des codes page. Ainsi, l’anglais, qui n’utilise pas de caractères accentués, est indépendant des codes page.

Gestion dynamique des codes page

Dans certains cas, la gestion des langues doit être dynamique, c’est-à-dire qu’elle ne dépend pas seulement du choix de la langue fait par l’utilisateur, mais également du contexte. Par exemple, si une table client contient des informations stockées directement dans la langue du client (l’adresse de livraison) et qu’elle n’est pas homogène pour toutes les lignes la table.

Dans ce cas, qui n’est pas pris en charge par l’ERP Divalto en standard, il sera éventuellement nécessaire de changer les codes page dynamiquement à l’exécution pour l’affichage des champs concernés.

Les fonctions XmeSetAttribut et XmeListSetAttribut permettent d’indiquer quel est le code à utiliser pour l’affichage ou la saisie de ces informations (attribut AN_CODE_PAGE).

 

Autres exemples d'utilisation d'un code page dynamique :

  • Menu affiché dans un arbre.
    Les choix du menu sont généralement affichés dans la langue de l'utilisateur et par défaut, les libellés d'un arbre sont affichés dans la langue des données. Si les deux langues ne sont pas identiques, il faut changer dynamiquement le code page appliqué à l'arbre.
     

  • Format d'affichage d'un champ.
    Le format d'affichage (propriété "Format" dans Xwin) est normalement traduit dans la langue de l'utilisateur mais les champs sont affichés dans la langue des données. Si les deux langues ne sont pas identiques, il faut changer dynamiquement le code page appliqué au champ.
     

  • Affichage de la liste des valeurs d'un multi-choix "normal" dans un multi-choix générique.
    Le zoom fournit un exemple de ce cas lorsqu'il affiche la liste des valeurs possibles d'une donnée multi-choix dans la fenêtre Filtres / Tris.
    Normalement, les valeurs sont traduites dans la langue de l'utilisateur, le multi-choix présentant ces valeurs est un multi-choix "liste" garni dynamiquement et, par défaut, les choix d'un multi-choix "liste" sont affichés dans la langue des données. Si les deux langues ne sont pas identiques, il faut changer dynamiquement le code page appliqué au multi-choix.

Pour appliquer le code page de la langue de l'utilisateur à un objet, affectez-lui un nom d'objet dans Xwin (propriété "Noms de l'objet" ; par exemple "code_page") et programmez :

1   type_date   1
XmeSetAttribut ("code_page", AN_CODE_PAGE, GetLanguageCodePage (GetLanguageCode (type_date)))
