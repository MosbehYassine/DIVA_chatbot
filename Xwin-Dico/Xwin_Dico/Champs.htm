Champs

 

Les paramètres d’un champ sont :
 

Nom

G

Nom du champ.

Libellé

G  +  L

Texte libre décrivant le champ.

Nom Odbc

G  +  L

Nom utilisé pour les requêtes Odbc.

 

 

 

Famille Caractéristiques

Nature

G

Nature du champ.

Taille

G

Taille du champ.

Taille gelée

G

Indique si la taille du champ est gelée ou non. Voir Geler le dictionnaire.

Position

G

Rappel de la position du champ par rapport à son antécédent direct.

La position d’un champ dans la table est affichée dans la zone Propriétés de l’objet courant de l’écran. Voir L'écran de l'éditeur de dictionnaire.

Décimales

G

Nombre de décimales pour une donnée numérique ou numérique,D.
Voir Natures.

Dimensions

G

Vous pouvez définir des tableaux jusque 4 dimensions. Spécifiez le nombre maximum d’éléments par dimension séparés par le caractère *.
Ex : 5*3 pour un tableau à 2 dimensions.

Position

G

Position de la donnée dans la table.

Champ virtuel

G

Indique si le champ est virtuel. Voir Champs virtuels.

 

 

 

Famille Présentation

Les familles Présentation,  Saisie et Aide  regroupent les paramètres du champ qui seront pris lors de l'insertion dans un masque.

Présentation

G  +  L

Type de présentation du champ (champ, multi-choix, case à cocher) lorsqu'il est inséré dans un masque.

Dictionnaire,choix

G  +  L

 

Liste des choix si la présentation choisie est un objet à choix multiples (multi-choix, groupe radio, case à cocher).

Noms de l'objet

G  +  L

 

Liste de noms pour les attributs dynamiques.

Format

G  +  L

 

Format d'affichage de l'objet.

Champ avec saisie obligatoire.

G  +  L

 

Conversion à effectuer lors de la saisie.

Famille Avancé

Alias

G  +  L

Cette propriété est uniquement utilisée lors de la génération automatique des liens.
Elle permet de donner un autre nom (ou plusieurs autres noms) au champ que le nom usuel. Ce nouveau nom masque le nom usuel du champ pendant la génération automatique des liens. Voir remarque ci-dessous.

Masqué pour Odbc

G  +  L

Si "oui" le champ n’apparaît pas dans la liste des colonnes lorsque le fichier est accédée depuis un driver ODBC.

Zone U

G  +  L

Indique que cette zone est réservée pour l'ajout de données par les partenaires. Dans le cadre des surcharges multiples, cette zone est extensible, il n'y a donc pas de limites quant à la taille des données que l'on peut placer sous une Zone U.
La gestion des surcharges multiples est décrite en détail dans la documentation Diva au chapitre : <Techniques de programmation><Surcharges multiples>

Masqué pour SQL

G  +  L

Si "oui", le champ n’apparaît pas dans le fichier SQL ; il n’est pas créé dans la table SQL. En effet, les Fichiers de données SQL ne connaissent pas la notion de sous-champ. Lorsqu’un champ a des sous-champs il faut choisir si c’est le champ ou les sous-champs qui doivent être définis dans la base SQL.

Binaire autorisé

G  +  L

Cette propriété ne concerne que les champs alpha et est utilisée par la fonction « Contrôle d’intégrité de fichier » de Xtools.dhop. Si elle n’est pas cochée, le contrôle d’intégrité signalera la présence de données binaires dans le champ. Si elle est cochée, ce champ de la table ne sera pas contrôlé.

Utilisable en Diva

G

Ne concerne que les champs virtuels. Indique que le champ virtuel ne doit pas être utilisé en Diva. Il ne peut alors qu'être utilisé par le driver Odbc.

Attribut

G  +  L

Prévu pour une utilisation ultérieure.

EDI

G  +  L

Prévu pour une utilisation ultérieure. (Echange de documents informatiques).

Valeur initiale moulinette

G  +  L

Valeur par défaut que prendra le champ dans les moulinettes permettant de passer d’une version de fichier à une autre.

Voir : Valeur initiale des nouveaux champs.

Regroupement dans Zoom

G  +  L

Nom de l'onglet sous lequel l'objet sera placé lors de la génération du Zoom.

Masqué pour masque

G  +  L

Ce champ n'apparaît pas dans la liste de données lors d'une insertion dans un masque depuis le dictionnaire.

Confidentialité

G  +  L

Permet de placer un code de confidentialité sur le champ. Si l'utilisateur n'a pas ce droit, le champ n'apparaît pas dans la liste des champs d'une table, et le champ ne peut être utilisé dans une requête SQL.

Multilingue

G + L

Indique que le champ peut être traduit à l'affichage. Voir le livre "Traduction des libellés multilingues" dans le manuel de référence d'Harmony.

La propriété multilingue d'un champ peut également être positionnée dans les masques. Cela permet de rendre un champ multilingue, alors que cela n'est pas prévu dans le dictionnaire.

G=global  L=local

 

Le bouton Mode Liste permet de revenir au mode liste (uniquement dans le cas où la saisie a été commencée en mode liste).

 

 

Remarques sur la propriété Alias

  • L’alias peut contenir plusieurs noms séparés par une virgule.

  • L’alias permet d’éviter de générer automatiquement des liens erronés entre les tables.
    Dans certains cas, un lien est généré à tort entre deux tables car le champ est présent     dans les deux tables mais avec une signification différente.
    Pour éviter de générer ces liens, il faut renseigner l’alias de ce champ avec un nom différent dans chacune des tables où il est présent. Si un champ a plusieurs significations dans une table, on peut mettre plusieurs noms dans l’alias, voire le nom usuel du champ si nécessaire.

    Exemple :
    Dictionnaire : GTFDD.dhsd
    Fichier des mouvements GTFAM avec table MOUV
    Fichier GTFPCF (clients, prospects, fournisseurs, représentants) avec les quatre tables CLI, FOU, VRP, PRO.

    Le champ Tiers existe dans les quatre tables de GTFPCF avec à chaque fois une signification différente. Dans la table CLI le champ Tiers désigne le code client, dans la table FOU le champ Tiers désigne le code fournisseur etc.
    Pour que la génération automatique des liens ne génére pas de liens erronés, il convient de donner au champ Tiers un alias différent pour chacune des tables de la manière suivante :
     - dans CLI  : CODECLI
     - dans FOU : CODEFOU
     - dans PRO : CODEPRO
     - dans VRP : CODEVRP
     - dans MOUV : CODECLI,CODEFOU

    Dans MOUV, Tiers a deux alias, car le champ peut contenir soit un code de client, soit un code de fournisseur. Dans ce cas, les liens de MOUV vers CLI et FOU seront générés.

    Par contre il n’y aura pas de lien entre MOUV et PRO puisque CODEPRO ne figure pas dans la table MOUV.
