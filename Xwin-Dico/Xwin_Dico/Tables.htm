Tables

 

Les paramètres d’une table sont :
 

Mnémonique

G  +  L

Nom de la table.

Libellé

G  +  L

Texte libre décrivant la table.

Nom Odbc

G  +  L

Nom utilisé pour les requêtes Odbc.

Masqué pour Odbc

G  +  L

Si "oui", la table n’apparaît pas dans la liste des tables lorsque le fichier est accédée depuis un driver Odbc.

 

 

 

  Famille Taille

(Mini xxx)

G  +  L

Taille en caractères de la table. Cette taille est celle que prend un enregistrement dans le fichier. La valeur Mini indiquée entre parenthèses indique la taille occupée par les champs de la table. Taille peut être supérieure pour laisser de la place dans les enregistrements.

Mémoire (mini  xxx)

G  +  L

Taille en caractères de l’enregistrement en mémoire. La taille en mémoire est supérieure à la taille si la table contient une zone packée. Si la table contient une zone packée, la taille en mémoire est au minimum la taille de la table augmentée de deux fois la taille de la zone packée. Voir Zone packée.
 

Famille Identifiant

Champ

G  +  L

Nom du champ qui sert d’identifiant. La taille de ce champ est de 1 caractère.

Valeur

G  +  L

Valeur du champ qui permet d’identifier l’enregistrement. Lorsque plusieurs tables sont stockées dans le même fichier, il faut bien sûr un identifiant qui permet de distinguer un enregistrement de la table A d’un enregistrement de la table B.

Si la valeur n’est pas un caractère affichable, vous pouvez saisir la valeur du code ANSI de ce caractère sur 3 positions. Exemple : 001 pour la valeur binaire 0x01.

Voir l’exemple ci-dessous.

 

 

 

Famille Confidentialité  (pour la gestion des confidentialités du RecordSql)

Champ

G  +  L

Nom du champ de la table qui contient le code de confidentialité permettant de lire la table depuis un RecordSql. C’est un champ alphanumérique de 4 caractères. Par convention, son nom est Conf.

Passe-partout

G  +  L

Nom du passe-partout permettant d'accéder à la table.
Voir dans la documentation <Programmation><RecordSql><RecordSql-Programmation><Condidentialités>

 

 

Le choix « Confidentialités tables », accessible par un clic droit sur le dictionnaire dans l’arbre, permet d’associer un nom de champ et un passe-partout à toutes les tables d’un dictionnaire. L’association n’est effectuée que si la table contient le champ confidentialité.

 

 

Famille Traitements

Après Read

L

Nom (facultatif) du traitement Diva Après Read qui sera appelé après chaque lecture par iRead, iPread, iSeek.

Avant Write

L

Nom (facultatif) du traitement Diva Avant Write qui sera appelé avant chaque écriture par iWrite.

Avant Rewrite

L

Nom (facultatif) du traitement Diva Avant Rewrite qui sera appelé avant chaque réécriture par iRewrite.

Avant Delete

L

Nom (facultatif) traitement Diva Avant Delete qui sera appelé avant chaque suppression par iDelete.

 

 

Vous trouverez des explications détaillées sur la saisie de ces quatre noms à la rubrique Définition d'un nom de traitement.

Exemple d’identifiant

Le fichier ccfdce contient 4 tables qui sont : c3, c4, c5, c8.

A l’intérieur d’un même fichier physique on va donc trouver des enregistrements de chacune de ces tables.

L’identifiant permet de savoir à quelle table appartient un enregistrement.

 

 

L’identifiant est placé à la même position dans toutes les tables. Ici, Ce1 est le premier champ de toutes les tables.
