DefProcDelete  Famille Thème

Fonction de suppression d'une ligne de tableau / arbre personnalisée
(appelée par XmeListConsultDefault)

 
Int DefProcDelete (Identifiant, Opération)

 
Paramètres :

Identifiant

Identificateur du tableau rendu par la fonction XmeListGetId.

Opération

Opération en cours (type B) :
LIST_SUPPRESSION : suppression d'une ligne ou de la sélection (sans copie dans le presse-papiers).
LIST_COUPER : couper d'une ligne ou de la sélection (avec copie dans le presse-papiers).

 
Votre fonction doit rendre :

  • TRUE si vous acceptez la suppression de la ligne en cours.

  • FALSE si vous refusez cette suppression.

 
Conditions d'exécution de la fonction :

Pour que XmeListConsultDefault fasse appel à DefProcDelete, vous devez :

  • Mettre le paramètre Perso de XmeListConsultDefault à la valeur TRUE.

  • Dans votre programme et avant tout appel à XmeListConsultDefault, placer le nom du module (qui peut être le programme courant) contenant la définition de DefProcDelete, dans la zone DefpModule de l'enregistrement Harmony.

 
Description de la fonction :

  • La fonction DefProcDelete est appelée par XmeListConsultDefault après la validation d'une suppression par l'utilisateur et avant la destruction de la ligne courante dans la liste. En cas de suppression d'une sélection, elle est appelée avant la destruction de CHAQUE ligne sélectionnée.

  • Elle peut être utilisée par exemple pour interdire la suppression sous certaines conditions ou pour effectuer une copie de sauvegarde des lignes supprimées.
    Remarque : Avant d'appeler DefProcDelete, XmeListConsultDefault fait pointer le courant de la liste sur la ligne à détruire et garnit l'enregistrement concerné avec le contenu de cette ligne.

  • La destruction de ligne(s) proprement dite continue à être prise en charge par XmeListConsultDefault.

  • Le paramètre Opération vous permet de savoir si DefProcDelete a été appelée à l'occasion d'une suppression -de ligne ou de la sélection- sans (LIST_SUPPRESSION) ou avec (LIST_COUPER) copie dans le presse-papiers.

  • Dans le cas d'une suppression dans un arbre, rappelons que les sous-niveaux d'un élément supprimé sont automatiquement détruits.
    DefProcDelete est appelée pour CHAQUE ligne détruite (donc pour l'élément " père " puis pour chaque " descendant ").
    Toutefois, au retour, l'autorisation de destruction N'est vérifiée QUE pour l'élément père : ses descendants sont toujours détruits (autrement dit, si vous donnez l'autorisation de détruire un père, vous ne pouvez pas refuser la destruction de ses descendants).
    En cas de suppression d'une sélection dans un arbre, rappelons que les pères sélectionnés sont tous de même niveau. L'autorisation de destruction est vérifiée pour CHACUN des éléments père (mais pas pour leurs descendants respectifs).

  • Lorsque l'utilisateur effectue un " Couper ", un en-tête de reconnaissance personnalisé peut être placé par XmeListConsultDefault dans le presse-papiers. Vous pouvez ensuite consulter cet en-tête lorsque l'utilisateur effectue le " Coller " correspondant. Pour tous les détails à ce sujet, reportez-vous à la rubrique consacrée à la fonction DefProcColler.

 

Remarque : En cas de " Couper ", la copie dans le presse-papiers a lieu AVANT les appels à DefProcDelete (donc sans possibilité de refus de cette copie).
 

Attention : DefProcDelete DOIT laisser l'élément courant de la liste inchangé.
 

Exemple :
 

;Programme PROG (schéma)

...

 

Function INT DefProcDelete (Ident, Operation)

1 Ident L

1 Operation B

1 retour X

beginf

   XmeListCurrent (Ident, Ligne)          ;lecture du courant

   IF ...                                 ;contrôle 

      retour = FALSE                      ;delete refusé 

   ELSE 

      retour = TRUE                       ;delete accepté 

   ENDIF 

   FRETURN (retour) 

endf

 

...

...

Harmony.DefpModule = 'PROG.dhop'          ;le programme lui-même

                                          ;avec personnalisation 

         XmeListConsultDefault (Ident, Ligne, ScrollBar32, \

   ENDSWITCH
