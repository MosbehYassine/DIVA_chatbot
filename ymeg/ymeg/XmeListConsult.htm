XmeListConsult  Famille Thème

Consultation d'un tableau

 
Char XmeListConsult (Identifiant)

 
Paramètre :

Identifiant

Identificateur du tableau rendu par la fonction XmeListGetId.

 

 

Valeur rendue par la fonction (type B) :

Il est conseillé d'ignorer cette valeur et de plutôt tester Harmony.Key pour identifier la touche tapée. En effet, toutes les touches et combinaisons de touches génèrent une valeur différente de Harmony.Key, y compris les touches "normales" (lettres, chiffres, etc.) qui génèrent la valeur K_ANSIKEY_OFFSET+nnn, où nnn est le code ANSI de la touche. Sinon :

  • Si un événement souris s'est produit, la valeur rendue est Espace.

  • Si un événement clavier s'est produit, la valeur rendue correspond au code de la touche tapée.
    Pour les caractères "normaux", il s'agit du code ANSI du caractère. Pour les touches spéciales, il s'agit de leur ancien code PC8 (Cf. Defines F_xxx de Zdiva), pour assurer la compatibilité des programmes conçus en versions 5 ou antérieures d'Harmony.

 

Description de la fonction :

  • XmeListConsult est la fonction à appeler pour proposer une consultation et attendre un événement sur un objet tableau.
    Elle NE peut être exécutée QUE si la page de masque contenant le tableau est la page courante.

  • La fonction affiche les lignes du tableau dont l'identifiant est fourni en paramètre (comme XmeListDisplay) puis se met en attente d'une frappe au clavier ou d'un événement souris significatif. Aucune modification des données n'est possible pour l'utilisateur.

  • Le contrôle est rendu au programme appelant dès qu'un événement clavier ou souris est produit par l'utilisateur :
    -     Si une touche du clavier a été tapée, la variable Harmony.Key est positionnée à la manière habituelle, de même que les indicateurs ShiftKey et ControlKey.
    -     Si un événement souris s'est produit, Harmony.Key est mis à 0.

  • Un délai peut être associé à la fonction XmeListConsult, de manière à ce que celle-ci rende la main à intervalles réguliers et ce, même si l'utilisateur ne produit aucun événement clavier ou souris. Pour tous les détails de mise en œuvre, consultez la rubrique consacrée à la fonction XmeSetTimer.

  • La fonction standard XmeListConsultDefault propose un traitement par défaut pour la plupart des événements concernant le tableau : déplacements au clavier ou à la souris, changement de la taille de la fenêtre, création – modification – suppression de lignes, sélections, copier – couper – coller.
    Cette fonction peut ou non être appelée pour chaque événement à traiter : par exemple, vous pouvez décider de reprogrammer les opérations de création, modification et suppression de lignes car le traitement standard ne convient pas, tout en conservant ce traitement standard pour les déplacements dans le tableau (Cf. exemple ci-dessous).

 

Exemple :

;Schéma de programmation d'une consultation par XmeListConsult

...

PUBLIC RECORD Appli.dhsd Ligne

PUBLIC RECORD DDSYS.dhsd ScrollBar32 Ascens

 

1 Ident L

1 Fini B

...

 

MAIN 

...

XmeLoad ("EOBJTAB")

XmeInfoPage ("EOBJTAB",1)

XmeSetWindowSize ("EOBJTAB",1,Harmony.Opara3,Harmony.Opara4)

 

Ident = XmeListGetId ("EOBJTAB",1,"TABLEAU",Ligne)

...

XmeDispv ("EOBJTAB",1,XME_MODE_GOTO)              ;affiche page tableau

 

Fini = FALSE

DO

   XmeListConsult (Ident)                         ;consultation 

   SWITCH Harmony.Key 

      CASE K_ESCAPE                               ;fin 

         Fini = TRUE 

 

      CASE Harmony.Key in (K_F3, K_INSERT)        ;création 

         ... 

 

      CASE K_F4                                   ;modification 

         ... 

 

      CASE Harmony.Key in (K_SF3, K_SUPPR)        ;suppression 

         ...

 

      DEFAULT                                     ;tous les autres événements 

         XmeListConsultDefault (Ident, Ligne, Ascens) 

   ENDSWITCH

WHILE Fini = FALSE

WEND

 

...

 

Remarques :

  • La fonction XmeListConsult NE peut être appelée QUE si la page de masque contenant le tableau est la page courante (ou une de ses pages panels).

  • XmeListConsult :
    -     Valide tous les boutons et choix de menu non nommés.
    -     Valide les boutons et choix de menu nommés, à condition qu'ils soient présents dans la liste des boutons valides du tableau (pour modifier cette liste, cliquez sur la ligne Boutons valides des propriétés du tableau).

  • Si l'utilisateur clique sur un bouton ou un choix de menu générant un point d'arrêt, la main est rendue au programme ; celui-ci peut récupérer le numéro du point d'arrêt dans Harmony.DataArret (attention, pas dans Harmony.Arret) ; après le traitement du point d'arrêt, vous pouvez bien entendu rappeler la fonction XmeListConsult mais un éventuel code de retour placé dans Harmony.Retour sera ignoré (ce code n'a de sens qu'à l'appel de l'instruction XmeNext).

  • Si l'utilisateur clique sur un bouton ou un choix de menu associé à un point de traitement, la séquence de traitement est exécutée ; au retour de cette séquence, Ywpf revient toujours à la consultation ; les données de la page courante (HORS tableau) sont automatiquement réaffichées ; un éventuel code de retour placé dans Harmony.Retour sera ignoré (ce code n'a de sens qu'au retour d'un traitement exécuté en saisie).

  • En consultation par XmeListConsult, tous les événements souris significatifs rendent la main. Attention, le numéro du point d'arrêt généré n'est pas transmis dans Harmony.Arret mais dans Harmony.DataArret. Les événements souris traités sont les suivants :
     
    -     "Clic tableau" quelconque.
    Outre le numéro du point d'arrêt lié au tableau transmis dans Harmony.DataArret, le programme peut récupérer tous les renseignements sur le clic produit (Cf. rubrique Evénements souris liés à l'objet tableau), avec en particulier le numéro de point de séquence de la donnée concernée si le clic a eu lieu sur une cellule en saisie (voir le cas suivant).
    Remarque : Si plusieurs tableaux sont affichés dans la page courante, tous les "clics tableau" sont transmis, même ceux ne concernant pas le tableau consulté ; utilisez alors Harmony.DataArret pour différencier les différents tableaux.
     
    -     Clic sur une donnée en saisie quelconque.
    Les paramètres Harmony.SourisSeq et Harmony.SourisPage sont garnis avec le numéro de point de séquence et le numéro de page de la donnée cliquée (Cf. rubrique Souris : Positionnements en consultation de masque).
    La donnée peut se trouver sur une ligne du tableau (voir le cas précédent) ou non.
    Remarque : Harmony.SourisSeq est mis à 0 si le clic n'a pas eu lieu sur une donnée en saisie ou si la main a été rendue au programme suite à une action clavier.
     
    -     Onglets.
    Attention    , seuls les onglets placés sur des pages non chaînées sont valides ; ceux placés sur des pages chaînées sont ignorés.

 

Appel d’un menu surgissant en consultation de tableau

Pour afficher un menu surgissant (popup-menu) à l’occasion d’une consultation de tableau, chargez la donnée Harmony.PopupMenu avec l’identifiant du menu à afficher, avant d’appeler XmeListConsult (exemple à la rubrique Menus : Chargement et affichage d'un menu).

 

Appel de l’aide associée à la page consultée

Avec Xwin, vous pouvez associer une aide à toute page de masque. Cette aide servira d’abord d’aide par défaut pour toutes les données présentes dans cette page. Il peut aussi être intéressant d’afficher cette aide si l’utilisateur tape Shift+F1 (touche standard d’appel de l’aide) alors que la page est en consultation par XmeListConsult. Pour ce faire, en réponse à la touche Shift+F1, appelez successivement les fonctions XmeInfoPage pour récupérer le nom du fichier d’aides et le numéro de l’aide associée à la page puis le fonction XmeHelp.
