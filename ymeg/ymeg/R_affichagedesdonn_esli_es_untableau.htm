Réaffichage des données liées à un tableau

1. Réaffichage au retour d'une interruption de saisie

Il faut distinguer deux cas de saisie :

  • La variable saisie est dans une ligne du tableau (XmeListInput) :
    Les données de la ligne saisie, ainsi que toutes les données de la page Xwin contenant le tableau, sont automatiquement réaffichées.
    Les données des autres lignes du même tableau, d'autres tableaux ou d'autres pages que la page courante ne sont pas réaffichées.
     
    Exemple :
    La ligne d'un tableau contient le champ "code article" et la page incluant le tableau une Bitmap Variable représentant l'image de cet article. La saisie du code est contrôlée par un point de traitement ou d'arrêt Après ; si le code est correct, on souhaite qu'au retour la ligne courante du tableau (affichant les différents champs de l'article) et l'image de l'article soient actualisées à l'écran pour correspondre au code nouvellement saisi. Le réaffichage de ces données est automatique.
     

  • La variable saisie n'est pas dans un tableau (XmeInput) :
    Seules les données hors tableau de la page courante sont automatiquement réaffichées.
    Le réaffichage des données des tableaux reste à la charge du programme (utilisez le cas échéant la fonction XmeListDisplay).

 

2. (Ré)affichage en consultation

Reprenons l'exemple précédent. On désire cette fois que la bitmap variable affiche toujours l'image de l'article couramment sélectionné. Lorsque l'utilisateur se déplace dans le tableau, il faut donc garnir la donnée bitmap puis actualiser l'écran.
 
En consultation (par exemple par XmeListConsult), si vous désirez actualiser à l'écran des données liées à la ligne courante mais situées hors du tableau, vous devez programmer explicitement le réaffichage (en général, en appelant la fonction XmeDispv).
 
Attention, si vous utilisez la fonction standard XmeListConsultDefault, vous devez programmer le réaffichage APRES l'appel à XmeListConsultDefault (car il faut attendre qu'elle ait calculé le nouvel élément courant).
